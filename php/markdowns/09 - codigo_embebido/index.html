    Código embebido

    Imagina una página HTML que se adapta al usuario en tiempo real: muestra la hora exacta, saluda por nombre, lista contenido desde una base de datos y cambia su estructura según condiciones. Eso es lo que permite el código embebido en PHP: insertar lógica del servidor dentro de tus archivos HTML para generar páginas dinámicas, seguras y útiles.

    El código embebido es importante porque convierte páginas estáticas en experiencias dinámicas sin complicar la estructura HTML. Esto nos da una base práctica de plantillas, formularios y páginas que responden a datos. Además, enseña buenas prácticas esenciales: separar presentación y lógica, validar y escapar entradas.

    Veamos un primer ejemplo simple:

    <!DOCTYPE html>
<html lang="es">
    <head>
        <meta charset="UTF-8">
        <title>Ejemplo de PHP embebido</title>
    </head>
    <body>

        <h1>Bienvenido a mi página</h1>

        <p>Hoy es:
            <?php
                echo date("d/m/Y");
            ?>
        </p>

    </body>
</html>

    Este ejemplo define la estructura de nuestra página web en html y añade lógica de programación a través de PHP.

    Cabe destacar que el ejemplo anterior podría simplificarse utilizando la forma abreviada para imprimir valores en HTML:

    <p>La hora actual es: <?= date("H:i:s") ?></p>

// Esto es equivalente a
// <p>La hora actual es: <?php echo date("H:i:s"); ?></p>

    Pintar elementos (botones, tablas, listas...)

    Una vez visto el principio de código embebido, vamos a ver cómo usar PHP dentro de HTML para "pintar" elementos: botones, tablas, listas y atributos dinámicos.

    Iremos paso a paso con ejemplos comentados, buenas prácticas y un ejemplo completo final que podrás copiar/pegar directamente.

    Principios básicos

    Para aprovechar al máximo el código embebido en PHP, es fundamental adoptar una serie de buenas prácticas que garantizan tanto la legibilidad del código como la seguridad de la aplicación. Estos principios ayudan a mantener el proyecto escalable y protegen al usuario final de vulnerabilidades comunes.

    El primer principio clave es separar la lógica de la presentación. La práctica recomendada es preparar todos los datos necesarios y tomar todas las decisiones de negocio (como bucles, condicionales y cálculos) en bloques PHP dedicados, idealmente ubicados en la parte superior del archivo o fuera del archivo de la vista. La sección HTML, o la "vista", debe quedar lo más limpia posible, conteniendo solo las sentencias de impresión (echo o <?=) y estructuras de control mínimas (foreach, if) para dibujar la interfaz, pero sin lógica compleja.

    En segundo lugar, la seguridad es primordial. Siempre se debe escapar la salida que proviene de fuentes no confiables (como datos introducidos por el usuario o datos recuperados de una base de datos) antes de imprimirlos en el HTML. Esto se logra mediante la función htmlspecialchars(), que convierte caracteres especiales de HTML (como <, >) a sus entidades correspondientes, previniendo así ataques de Cross-Site Scripting (XSS) donde un atacante podría inyectar código malicioso en la página.

    Finalmente, es vital manejar correctamente la codificación de datos según su destino. Cuando se incrustan valores en parámetros de URL, se debe utilizar la función urlencode() para asegurar que caracteres especiales o espacios se transformen en un formato seguro para la web. Si se necesita incrustar estructuras de datos más complejas, como objetos o arrays, dentro de atributos HTML (como los atributos data-... de HTML5), se debe usar json_encode() para serializar el dato, seguido de htmlspecialchars() para asegurarse de que la cadena JSON sea segura antes de ser pintada.

    Veamos un ejemplo completo:

    <?php
// =================================================================
// 1. LÓGICA (PHP superior): Prepara los datos y las decisiones aquí.
// =================================================================

// 1.1. Dato que viene de una fuente externa (ej: un formulario o la base de datos)
// Contiene caracteres especiales (HTML) y espacios que deben ser escapados/codificados.
$nombre_usuario_bd = "O'Malley";
$mensaje_usuario_bd = "Haz clic <a href='malicioso.com'>aquí</a>.";
$id_producto = 456;
$nombre_producto = "Lámpara LED"; // Contiene un espacio

// 1.2. Prepara la salida: Escapa la salida ANTES de la presentación.
$nombre_seguro = htmlspecialchars($nombre_usuario_bd);
$mensaje_seguro = htmlspecialchars($mensaje_usuario_bd);
$nombre_url_seguro = urlencode($nombre_producto);

// =================================================================
// 2. PRESENTACIÓN (HTML + PHP mínimo): La vista lo más limpia posible.
// =================================================================
?>
<!DOCTYPE html>
<html lang="es">
    <head>
        <meta charset="UTF-8">
        <title>Ejemplo de Escapado Seguro</title>
    </head>
    <body>

        <h1>Bienvenido, <?= $nombre_seguro ?></h1>

        <p>Tu último mensaje (escapado):</p>
        <div style="border: 1px solid #ccc; padding: 10px;">
            <?= $mensaje_seguro ?>
        </div>
        <p>
            <a href="detalle.php?id=<?= $id_producto ?>&nombre=<?= $nombre_url_seguro ?>">
                Ver Producto ID: <?= $id_producto ?>
            </a>
            </p>

        <p>Página generada el: <?= date("d/m/Y H:i:s") ?></p>

    </body>
</html>

    La estructura de código embebido presentada ejemplifica las mejores prácticas para mantener la claridad del código y proteger la aplicación, basándose en una clara división de responsabilidades:

    El primer aspecto crucial es la Lógica Superior, donde se centraliza todo el procesamiento y la preparación de datos. Esto implica que tareas como la inicialización de variables ($nombre_seguro, $mensaje_seguro), la realización de cálculos y, de manera crítica, la aplicación de medidas de seguridad como htmlspecialchars() y urlencode(), se llevan a cabo en el bloque PHP inicial, antes de que se genere cualquier salida HTML. Al concentrar estas operaciones, se asegura que las decisiones de negocio y de seguridad se tomen en un solo lugar, manteniendo la lógica separada del aspecto visual.

    En contraste, la Presentación Limpia se refiere a que la sección HTML debe limitarse a la tarea de mostrar la interfaz. En esta área, solo se permite la inyección de los valores a través de etiquetas de eco, preferiblemente utilizando el short echo tag (<?= ... ?>). La vista simplemente "pinta" los datos que PHP le proporciona, sin tener que preocuparse por la lógica de negocio o cómo sanear las variables. Esta clara separación de responsabilidades hace que el código sea mucho más legible, ya que el desarrollador puede centrarse en la estructura HTML sin distraerse con el procesamiento de datos.

    Finalmente, la Seguridad se materializa en cómo las funciones de saneamiento protegen la integridad de la página. Por ejemplo, al aplicar htmlspecialchars(), una cadena potencialmente maliciosa como <a href='malicioso.com'>aquí</a> es convertida en entidades HTML (&lt;a href=&#039;malicioso.com&#039;&gt;aquí&lt;/a&gt;). Esta conversión garantiza que el navegador renderice el código como texto literal inofensivo en lugar de ejecutarlo como un enlace funcional, previniendo eficazmente ataques de Cross-Site Scripting (XSS). De manera similar, la función urlencode() se encarga de que las variables destinadas a URLs, como $nombre_producto, se transformen en un formato seguro (L%C3%A1mpara+LED), garantizando que la URL sea válida y se interprete correctamente por el servidor.

    Guarda este código como un archivo .php para ver cómo PHP inyecta contenido seguro y dinámico directamente en el HTML.

    Botones

    Una de las aplicaciones más inmediatas del código PHP embebido es la capacidad de modificar dinámicamente el texto o los atributos de elementos HTML básicos, como los botones. Esto permite que la interfaz de usuario se adapte instantáneamente al estado de la aplicación o a la información del usuario, sin necesidad de complejos scripts del lado del cliente.

    El caso más común es cambiar el texto de un botón (<button>) o el valor de un campo de envío (<input type="submit">) para reflejar una acción contextual. Para esto, se utiliza la etiqueta de short echo (<?= ... ?>) directamente dentro del elemento HTML.

    Imaginemos que el texto del botón debe cambiar dependiendo de si un usuario ha iniciado sesión o no.

    <?php
// Lógica superior: Define la variable con el texto deseado
$usuario_logueado = true; // Simula la variable de sesión
$texto_boton = $usuario_logueado ? "Ir al Panel" : "Iniciar Sesión";
$clase_boton = $usuario_logueado ? "btn-success" : "btn-primary";
?>

<!DOCTYPE html>
<html lang="es">
<head>
    <title>Botón Dinámico</title>
    <style> .btn-success { background-color: green; color: white; } .btn-primary { background-color: blue; color: white; } </style>
</head>
<body>

    <button type="submit" class="<?= $clase_boton ?>">
        <?= $texto_boton ?>
    </button>

</body>
</html>

    El ejemplo de botón dinámico ilustra perfectamente la separación de responsabilidades entre la lógica del servidor y la presentación visual, que es la esencia del código embebido.

    El proceso se inicia con la Lógica Superior, donde el bloque inicial de PHP se encarga de determinar el estado y las propiedades finales del elemento HTML. En nuestro ejemplo, el valor de la variable $usuario_logueado dicta qué texto y qué clase CSS son apropiados. Es en este punto donde se toman todas las decisiones: ¿El usuario ve el texto "Ir al Panel" o "Iniciar Sesión"? ¿El botón tendrá la clase btn-success o btn-primary? El resultado de estas decisiones se almacena en variables como $texto_boton y $clase_boton, preparadas para su uso posterior.

    Una vez establecidos los valores, la Presentación Limpia entra en juego. El código HTML permanece inalterado en su estructura, actuando como una plantilla. Se utiliza la etiqueta de short echo (<?= ... ?>) para la Inyección de Texto, insertando la cadena final almacenada en $texto_boton directamente como el contenido visible dentro de la etiqueta <button>. De forma análoga, la Inyección de Atributos se realiza dentro de la propia etiqueta, donde la sentencia class="<?= $clase_boton ?>" inserta dinámicamente el nombre de la clase CSS. Esta técnica es fundamental porque demuestra la capacidad de PHP para generar código HTML completamente variable, modificando tanto el contenido visible como los atributos internos en función de la lógica del servidor.

    Veamos otro ejemplo de esto:

    <?php
    // =================================================================
    // 1. LÓGICA (PHP superior): Define estado, clases y contenido.
    // =================================================================

    // Simula variables de estado de la aplicación
    $esAdministrador = true;
    $itemEnEdicion = false; // Indica si el recurso está actualmente bloqueado o no

    // 1.1. Determinación de Atributos y Clases
    $esPrimario = $esAdministrador && $itemEnEdicion; // Es primario solo si es admin Y está editando
    $estaDeshabilitado = !$esAdministrador || !$itemEnEdicion; // Está deshabilitado si NO es admin O NO está editando

    // 1.2. Construcción de Clases CSS y Contenido
    $clases_btn = ['btn', 'btn-sm']; // Clases base
    if ($esPrimario) {
        $clases_btn[] = 'btn-danger';
    } else {
        $clases_btn[] = 'btn-secondary';
    }

    $texto_btn = $estaDeshabilitado ? "Ver Bloqueado" : "Finalizar Edición";

    // Nota: e() es una función de framework común para htmlspecialchars()
    // Implode junta el array de clases en una cadena separada por espacios
    $clases_finales = implode(' ', $clases_btn);
?>

<button class="<?= htmlspecialchars($clases_finales) ?>" <?= $estaDeshabilitado ? 'disabled' : '' ?>>
    <?= htmlspecialchars($texto_btn) ?>
</button>

    Este ejemplo demuestra la manipulación dinámica en su forma más pura, donde la lógica del servidor se traduce directamente en la estructura y los atributos del HTML.

    En la Lógica Superior, las variables booleanas ($esAdministrador, $itemEnEdicion) sirven como base para determinar el estado final y la apariencia del botón. PHP utiliza operadores de lógica booleana (&& para Y, || para O) para calcular variables de estado clave ($esPrimario, $estaDeshabilitado), encapsulando así reglas de negocio complejas en una zona del código dedicada. Después de este cálculo, se realiza una construcción condicional de clases CSS dentro de un array, que posteriormente se une (implode) en una única cadena separada por espacios, quedando lista para su inyección.

    La sección de Presentación ejemplifica dos técnicas fundamentales de inyección de atributos. Primero, el atributo class recibe la cadena final de clases CSS (por ejemplo, btn btn-sm btn-secondary). Segundo, y más notable, el atributo de estado disabled se inyecta utilizando una expresión ternaria concisa: <?= $estaDeshabilitado ? 'disabled' : '' ?>. Esta expresión evalúa la variable booleana $estaDeshabilitado: si es verdadera, inyecta la palabra clave disabled (habilitando el atributo); si es falsa, inyecta una cadena vacía, dejando el botón funcional. Esta capacidad de PHP para controlar de manera limpia y concisa no solo el contenido visible, sino la existencia y el valor de los atributos, es crucial para crear interfaces de usuario completamente reactivas a la lógica del servidor.

    Vamos a ver un último ejemplo avanzado donde se muestra una técnica crucial en el desarrollo web moderno: utilizar PHP para inyectar estructuras de datos complejas (como objetos o arrays asociativos) directamente en atributos HTML. Esto permite que el script de PHP alimente datos listos para ser consumidos por el código JavaScript del lado del cliente.

    El script utiliza json_encode() para convertir un array asociativo de PHP en una cadena de texto válida con formato JSON, que luego se inyecta de manera segura en un atributo data-... de HTML5.

    <?php
    // =================================================================
    // 1. LÓGICA (PHP superior): Define la estructura de datos a inyectar.
    // =================================================================

    // Array asociativo que contiene la información del usuario
    $data_usuario = [
        'id' => 5, 
        'name' => 'María', 
        'rol' => 'editor' 
        // Nota: El array original fue ampliado con 'rol' para mostrar complejidad.
    ];

    // 1.1. Preparación de la salida para inyección:
    // 1. Convertir el array de PHP en una cadena JSON válida.
    $json_data = json_encode($data_usuario);

    // 2. Escapar la cadena JSON para que sea segura dentro de un atributo HTML.
    // (Asumimos 'e()' es un alias para htmlspecialchars(), práctica común en frameworks).
    $json_seguro = htmlspecialchars($json_data, ENT_QUOTES, 'UTF-8'); 
?>

<button data-user="<?= $json_seguro ?>" onclick="handleClick(this)">
    Ver detalles de <?= htmlspecialchars($data_usuario['name']) ?>
</button>

<script>
    function handleClick(btn) {
        // 1. Recupera la cadena JSON del atributo 'data-user'.
        const userJson = btn.getAttribute('data-user');

        // 2. Parsea la cadena JSON a un objeto JavaScript.
        const userObject = JSON.parse(userJson);

        console.log("ID del usuario:", userObject.id); // Salida: 5
        console.log("Nombre:", userObject.name);     // Salida: María
        console.log("Rol:", userObject.rol);         // Salida: editor
    }
</script>

    Este ejemplo ilustra el paso final en la interacción entre el servidor y el cliente: la transferencia de datos estructurados de forma segura.

    El proceso comienza en la Lógica Superior con la función json_encode(), que tiene la responsabilidad de serializar el array asociativo de PHP en una cadena de texto que cumple estrictamente con el formato JSON. Una vez generada la cadena JSON, esta es tratada con htmlspecialchars() para neutralizar cualquier carácter que pudiera romper el HTML (principalmente comillas), garantizando así que la inyección de la cadena en el atributo HTML sea completamente segura y que no se produzcan vulnerabilidades XSS.

    En la capa de Presentación, la cadena JSON, ya escapada, se inyecta en un atributo personalizado de HTML5, en este caso data-user. Los atributos data- son el canal estándar y limpio para almacenar datos de configuración o estado para JavaScript. Finalmente, en el lado del cliente, la función JavaScript (handleClick(btn)) recupera esta cadena JSON del atributo mediante btn.getAttribute('data-user'). El paso crucial aquí es el uso de JSON.parse() en JavaScript, que toma la cadena de texto recuperada de HTML y la convierte en un objeto JavaScript totalmente funcional. Este patrón es esencial para desarrollar interfaces altamente interactivas, ya que permite que PHP prepare la información completa del recurso (nombre, ID, rol, estado, etc.) y la entregue de manera eficiente en un solo paso al código de cliente.

    Tablas

    Una de las tareas más comunes e importantes del código PHP embebido es la generación dinámica de tablas HTML. Las tablas son la forma estándar de mostrar colecciones de datos estructurados, como listas de usuarios, registros de base de datos o resultados de búsqueda, lo que las convierte en un pilar de cualquier aplicación web basada en datos. La clave para generar estas estructuras reside en el uso combinado y eficiente de las estructuras de control repetitivas de PHP, como foreach o for, junto con las etiquetas HTML de tabla (<table>, <tr>, <td>).

    El proceso para transformar un conjunto de datos (normalmente un array) en una tabla HTML sigue un flujo de trabajo bien definido para asegurar la separación de lógica y presentación. Todo comienza con la Lógica Superior, donde el bloque inicial de PHP se encarga de recuperar el array de datos, ya sea desde una base de datos o desde cualquier otra fuente, realizando cualquier preparación o filtrado necesario antes de la presentación. Una vez listos los datos, se define la Estructura Base en HTML, que implica la apertura de las etiquetas <table>, <thead> y la fila de cabecera (<tr>) con sus respectivas etiquetas de título (<th>).

    El corazón del proceso es el Bucle de Filas, donde se inicia una estructura repetitiva (foreach) que itera sobre cada elemento individual del array de datos. Por cada elemento en el array, el código se intercala con el HTML para proceder a la Generación de Celdas. En este punto, se genera una nueva fila (<tr>) y se inyecta dinámicamente el valor de cada campo del elemento en las celdas (<td>) mediante el short echo tag (<?= ... ?>), asegurando que la salida se escape correctamente. Finalmente, una vez que el bucle ha procesado todos los registros, se procede al Cierre de la tabla con las etiquetas HTML correspondientes. Este enfoque garantiza que, independientemente del volumen de datos, PHP genere automáticamente el número exacto de filas requerido, manteniendo el código de la plantilla limpio, conciso y libre de repetición manual de código.

    Veamos un ejemplo de esto:

    <?php
    // =================================================================
    // 1. LÓGICA SUPERIOR: El Array de Datos (Simulación DB)
    // =================================================================
    $users = [
        ['id' => 1, 'name' => 'Ana', 'email' => 'ana@example.com'],
        ['id' => 2, 'name' => 'Luis <script>alert("XSS");</script>', 'email' => 'luis@example.com'], // Dato malicioso
        ['id' => 3, 'name' => 'María', 'email' => 'maria@example.com'],
    ];

    // Nota: Asumimos una función e() como alias para htmlspecialchars(),
    // que es la práctica estándar en muchos frameworks modernos.
    // Usamos htmlspecialchars() en este ejemplo para mayor claridad didáctica.
    function e($str) {
        return htmlspecialchars($str, ENT_QUOTES, 'UTF-8');
    }

?>

<table class="table-striped">
    <thead>
        <tr>
            <th>ID</th>
            <th>Nombre</th>
            <th>Email</th>
            <th>Acciones</th>
        </tr>
    </thead>
    <tbody>
        <?php foreach ($users as $user): ?>
            <tr>
                <td><?= e($user['id']) ?></td>

                <td><?= e($user['name']) ?></td>

                <td><a href="mailto:<?= urlencode($user['email']) ?>"><?= e($user['email']) ?></a></td>

                <td>
                    <a class="btn btn-sm btn-info" href="edit.php?id=<?= urlencode($user['id']) ?>">Editar</a>

                    <form method="post" action="delete.php" style="display:inline">
                        <input type="hidden" name="id" value="<?= e($user['id']) ?>">
                        <button type="submit" class="btn btn-sm btn-danger" onclick="return confirm('¿Eliminar este usuario?')">Eliminar</button>
                    </form>
                </td>
            </tr>
        <?php endforeach; ?>
    </tbody>
</table>

    El script de la tabla de usuarios es un compendio de las mejores prácticas de código embebido, demostrando cómo se combina la generación dinámica de contenido con la seguridad esencial y la interacción web.

    La generación de las filas se gestiona mediante la Iteración y Filas, utilizando la estructura de control <?php foreach ($users as $user): ?>. Esta sentencia garantiza que se genere una fila <tr> exacta por cada registro en el array de usuarios. La sintaxis alternativa, con el uso de dos puntos (:) y endforeach;, es clave aquí, ya que minimiza la presencia de código PHP en la vista, manteniendo el HTML como el lenguaje dominante y facilitando su lectura.

    La Seguridad (Prevención XSS) se pone de manifiesto en la celda del nombre: la línea <td><?= e($user['name']) ?></td> es fundamental. Cuando un dato contiene código malicioso (como el ejemplo del script de "Luis"), la función e() (que actúa como un alias de htmlspecialchars()) convierte los caracteres peligrosos, como < y >, en entidades HTML. Esto neutraliza la amenaza al asegurar que el navegador renderice el código como texto literal inofensivo en lugar de ejecutarlo como JavaScript.

    En cuanto a la Inyección de Enlaces, el script utiliza el enfoque correcto para los hipervínculos dinámicos. Para la inyección de la dirección de correo en el atributo href="mailto:...", se emplea urlencode() para garantizar que la dirección sea válida y se interprete correctamente dentro de la URL. Simultáneamente, se utiliza la función e() para imprimir la dirección de correo como texto visible del enlace, manteniendo la consistencia en el saneamiento de la salida.

    Finalmente, la sección de Acciones con Formularios (POST) ilustra la práctica recomendada para operaciones sensibles, como eliminar un registro. Dado que estas acciones modifican el estado de la aplicación, no deben realizarse mediante un simple enlace GET. En su lugar, se genera un pequeño formulario individual por fila. La ID del usuario se inyecta de forma segura en un campo oculto (<input type="hidden">), asegurando que el dato se envíe al script de procesamiento mediante el método POST, lo que es fundamental para proteger la integridad y el estado de la aplicación.

    Listas

    La generación de listas HTML ordenadas (<ol>) y no ordenadas (<ul>) a partir de colecciones de datos sigue exactamente el mismo principio que la creación de tablas, pero con una estructura de etiquetas más simple. Este método es esencial para mostrar menús de navegación, listas de resultados, comentarios o cualquier conjunto de elementos sin formato tabular.

    Al igual que con las tablas, la clave reside en utilizar el bucle foreach para iterar sobre el array de datos, generando un elemento de lista (<li>) por cada registro.

    Veamos un ejemplo donde se muestra cómo generar una lista no ordenada a partir de un array de páginas (simulando un menú de navegación), utilizando htmlspecialchars() para el texto visible y urlencode() para la URL en el atributo href.

    <?php
// =================================================================
// 1. LÓGICA SUPERIOR: Array de datos
// =================================================================
$paginas_menu = [
    ['texto' => 'Inicio', 'url' => '/home'],
    ['texto' => 'Productos y Servicios', 'url' => '/productos?tipo=general'],
    ['texto' => 'Contacto & Ayuda', 'url' => '/contacto'],
    ['texto' => 'Malicioso <script>', 'url' => '/test'], // Dato malicioso
];

// Función de saneamiento (alias de htmlspecialchars)
function e($str) {
    return htmlspecialchars($str ?? '', ENT_QUOTES, 'UTF-8');
}
?>

<nav>
    <ul class="menu-principal">
        <?php foreach ($paginas_menu as $pagina): ?>

            <li class="<?= $pagina['texto'] === 'Contacto & Ayuda' ? 'resaltado' : '' ?>">

                <a href="<?= urlencode($pagina['url']) ?>">
                    <?= e($pagina['texto']) ?>
                </a>
            </li>

        <?php endforeach; ?>
    </ul>
</nav>

    El bucle foreach actúa como el motor central que genera el esqueleto de la lista, ya sea ordenada (<ol>) o no ordenada (<ul>). En cada iteración, el bucle genera un elemento de lista (<li>) con un enlace (<a>) anidado en su interior, logrando que la estructura HTML se adapte al número exacto de elementos del array de datos. La eficiencia del código embebido se manifiesta en la capacidad de PHP para inyectar lógica y seguridad en tres puntos clave:

    En primer lugar, la Inyección de Atributos Dinámicos en <li> permite que la presentación cambie en función de las condiciones del servidor. Esto se logra mediante una expresión ternaria concisa que evalúa el estado del ítem (por ejemplo, si es la página actual o un elemento destacado), inyectando una clase CSS específica para permitir el resaltado visual.

    En segundo lugar, la Inyección Segura de URL garantiza que los enlaces generados sean funcionales y válidos. El atributo href del enlace utiliza la función urlencode() para codificar cualquier carácter especial, espacio o parámetro que contenga la URL, asegurando que el navegador la interprete correctamente.

    Finalmente, la Inyección Segura de Texto es esencial para la protección contra ataques XSS. El texto visible del enlace emplea la función e() (alias de htmlspecialchars()) para escapar el contenido. De esta forma, cualquier cadena con potencial malicioso, como la inyección de etiquetas <script>, es neutralizada y se muestra al usuario como texto simple, manteniendo la seguridad e integridad del menú de navegación.

    Este patrón de contenedor de lista seguido por un bucle foreach para generar los <li>s es el estándar de la industria para generar estructuras de navegación o cualquier tipo de listado de datos dinámicos.

    Atributos Dinámicos y Prácticas Seguras: Un Resumen Final

    El uso de código embebido en PHP para generar elementos HTML dinámicos culmina en la capacidad de controlar no solo el contenido visible, sino también los atributos de las etiquetas (class, href, data-, disabled, etc.). Sin embargo, es en este punto donde la seguridad se vuelve más crítica, ya que inyectar valores directamente en atributos puede abrir vulnerabilidades si no se aplica el saneamiento correcto.

    PHP permite inyectar contenido dinámico dentro de cualquier atributo HTML. Esto se logra mediante expresiones ternarias y la inyección de cadenas construidas, lo que proporciona un control absoluto sobre el aspecto y el estado funcional del elemento.

    1. Estado Funcional (Booleanos): Atributos como disabled, readonly o checked se controlan con ternarios concisos. Se inyecta el nombre del atributo si la condición es verdadera y una cadena vacía si es falsa.

      // Inyecta 'disabled' si la variable es TRUE
<button <?= $stock_agotado ? 'disabled' : '' ?>>Comprar</button>

    2. Clases Condicionales (Arrays): Para construir la cadena de clases CSS (class="..."), es una práctica limpia generar primero un array de clases en la lógica superior y luego usar implode(' ', $array_clases) para inyectar una cadena final y segura en el atributo.

      <?php $clases = ['btn']; if ($es_admin) $clases[] = 'btn-lg'; ?>
<a class="<?= htmlspecialchars(implode(' ', $clases)) ?>">Botón</a>

    La Regla de Oro: Prácticas de Saneamiento Obligatorias

    Para garantizar que la aplicación sea segura y prevenir las vulnerabilidades de XSS (Cross-Site Scripting) y la ruptura de HTML, la inyección de datos debe seguir rigurosos protocolos de saneamiento según el destino de la inyección:

    Destino del Dato Propósito Función de Saneamiento
    Contenido visible o Atributos generales (value, title, alt) Prevenir XSS htmlspecialchars($data)
    Atributos de URL (href, src, action) Garantizar que la URL sea válida urlencode($data)
    Atributos data-... (Para JavaScript) Prevenir inyección de JSON inválido json_encode($data) seguido de htmlspecialchars()
