    Formularios

    En el apartado anterior, estudiamos cómo el cliente puede enviar datos al servidor a través de los métodos GET y POST. Ahora, nos centraremos en la herramienta principal que permite a los usuarios generar esas peticiones de forma estructurada e interactiva: el formulario HTML. Los formularios son el corazón de la web dinámica; son el puente que permite a los usuarios comunicarse con nuestra aplicación, ya sea para iniciar sesión, realizar una búsqueda, publicar un comentario o realizar una compra.

    Un formulario es un conjunto de elementos de interfaz definidos por la etiqueta <form> en HTML. Esta etiqueta tiene dos atributos fundamentales que determinan su comportamiento:

    1. action: Especifica la URL del script de servidor (p. ej., procesar_datos.php) que recibirá y procesará la información del formulario.
    2. method: Indica el método HTTP que se usará para enviar los datos, que casi siempre será get o post.

    Dentro del formulario, encontramos los diferentes campos o controles que el usuario rellenará, como campos de texto (<input type="text">), áreas de texto (<textarea>), botones de selección (<select>, <input type="radio">) y casillas de verificación (<input type="checkbox">). Cada uno de estos campos debe tener un atributo name, que es el vínculo esencial entre el HTML y PHP. El valor de este atributo name se convertirá en la clave dentro de los arrays superglobales $_GET o $_POST en nuestro script de servidor.

    En este apartado, aprenderemos a construir formularios HTML robustos, exploraremos los diferentes tipos de campos y, lo más importante, veremos cómo recibir, validar y procesar los datos que nos envían los usuarios de forma segura y eficiente en PHP.

    Creando Nuestros Primeros Formularios

    El ejemplo más fundamental es un formulario que se envía a sí mismo. Crearemos un único fichero, saludo.php, que tendrá una doble responsabilidad:

    1. Mostrar el formulario HTML cuando se visita la página por primera vez.
    2. Procesar los datos cuando el usuario envía el formulario y mostrar un resultado.

    Para diferenciar entre estas dos situaciones, usaremos la variable global $_SERVER['REQUEST_METHOD'], que nos dirá si la página fue solicitada con GET (la primera visita) o POST (tras enviar el formulario).

    <?php
    // 1. Inicializamos una variable para el mensaje de saludo.
    $saludo = "";

    // 2. Comprobamos si el formulario ha sido enviado (si la petición es de tipo POST).
    if ($_SERVER['REQUEST_METHOD'] == 'POST') {

        // 3. Obtenemos el nombre del array $_POST.
        // Usamos htmlspecialchars() por seguridad, para prevenir ataques XSS.
        $nombre = htmlspecialchars($_POST['nombre']);

        // 4. Preparamos el mensaje de saludo.
        if (!empty($nombre)) {
            $saludo = "¡Hola, " . $nombre . "!";
        } else {
            $saludo = "Por favor, introduce tu nombre.";
        }
    }
?>
<!DOCTYPE html>
<html lang="es">
    <head>
        <meta charset="UTF-8">
        <title>Formulario de Saludo</title>
    </head>
    <body>

        <form action="saludo.php" method="post">
            <label for="nombre">Introduce tu nombre:</label>
            <input type="text" id="nombre" name="nombre">
            <button type="submit">Enviar</button>
        </form>

        <?php
        // 5. Mostramos el mensaje de saludo si no está vacío.
        if (!empty($saludo)) {
            echo "<h2>" . $saludo . "</h2>";
        }
        ?>

    </body>
</html>

    EL funcionamiento de este formulario es muy simple:

    1. La Primera Visita (Petición GET): Cuando abres saludo.php en el navegador, la petición es de tipo GET. El bloque if ($_SERVER['REQUEST_METHOD'] == 'POST') es falso, por lo que el código de procesamiento se ignora. La variable $saludo permanece vacía y la página simplemente muestra el formulario HTML.

    2. El Envío del Formulario (Petición POST): Cuando escribes tu nombre y pulsas "Enviar", el navegador realiza una nueva petición a saludo.php, pero esta vez con el método POST.

      • Ahora, la condición del if es verdadera y el código de procesamiento se ejecuta.

      • El script recupera el valor del campo de texto a través de $_POST['nombre'] (la clave 'nombre' coincide con el atributo name del <input>).

      • Se construye el mensaje de saludo y se guarda en la variable $saludo.

      • Finalmente, la página HTML se vuelve a renderizar, pero esta vez, como $saludo ya no está vacía, el echo final muestra el mensaje debajo del formulario.

    Otro ejemplo: Formulario de Login

    En este ejemplo se simulará una pantalla de inicio de sesión. El usuario introducirá un nombre y una contraseña. El script PHP comprobará si coinciden con unos valores predefinidos y mostrará un mensaje de bienvenida o un mensaje de error. Usaremos de nuevo un único fichero que se procesa a sí mismo.

    <?php
    // --- CONFIGURACIÓN ---
    // Definimos el usuario y la contraseña válidos.
    // En una aplicación real, estos datos vendrían de una base de datos.
    define('USUARIO_VALIDO', 'admin');
    define('PASSWORD_VALIDO', '1234');

    // --- LÓGICA DEL FORMULARIO ---
    // Inicializamos las variables para los mensajes.
    $mensaje = "";
    $clase_mensaje = ""; // Para darle un estilo CSS al mensaje (error o éxito)

    // Comprobamos si el formulario ha sido enviado.
    if ($_SERVER['REQUEST_METHOD'] == 'POST') {
        // Obtenemos los datos enviados, aplicando una limpieza básica.
        $usuario_enviado = htmlspecialchars($_POST['usuario']);
        $password_enviada = htmlspecialchars($_POST['password']);

        // Comprobamos si las credenciales son correctas.
        if ($usuario_enviado == USUARIO_VALIDO && $password_enviada == PASSWORD_VALIDO) {
            // Si son correctas, preparamos un mensaje de éxito.
            $mensaje = "¡Bienvenido, " . USUARIO_VALIDO . "! Has iniciado sesión correctamente.";
            $clase_mensaje = "exito";
        } else {
            // Si son incorrectas, preparamos un mensaje de error.
            $mensaje = "Error: El nombre de usuario o la contraseña son incorrectos.";
            $clase_mensaje = "error";
        }
    }
?>
<!DOCTYPE html>
    <html lang="es">
    <head>
        <meta charset="UTF-8">
        <title>Formulario de Login</title>
        <style>
            body { font-family: sans-serif; }
            .error { color: red; font-weight: bold; }
            .exito { color: green; font-weight: bold; }
            form { border: 1px solid #ccc; padding: 20px; max-width: 300px; }
        </style>
    </head>
    <body>

        <h2>Iniciar Sesión</h2>

        <form action="login.php" method="post">
            <div>
                <label for="usuario">Usuario:</label><br>
                <input type="text" id="usuario" name="usuario">
            </div>
            <br>
            <div>
                <label for="password">Contraseña:</label><br>
                <input type="password" id="password" name="password">
            </div>
            <br>
            <div>
                <button type="submit">Entrar</button>
            </div>
        </form>

        <?php
        // Si hay un mensaje que mostrar (de éxito o error), lo mostramos aquí.
        if (!empty($mensaje)) {
            echo "<p class='" . $clase_mensaje . "'>" . $mensaje . "</p>";
        }
        ?>

    </body>
</html>

    Veamos ahora como funciona este forumlario que emula un login simple:

    1. Credenciales "en Memoria": Al principio del script, usamos define() para establecer el usuario y la contraseña correctos. Esto nos sirve para simular una base de datos en este ejemplo simple.

    2. Lógica de Comprobación: Cuando el formulario se envía (method="post"), el bloque if principal se ejecuta. Recupera los valores de los campos usuario y password de $_POST. La línea if ($usuario_enviado == USUARIO_VALIDO && $password_enviada == PASSWORD_VALIDO) es el núcleo de la validación: comprueba si ambas condiciones son verdaderas.

    3. Retroalimentación al Usuario: Dependiendo del resultado de la comprobación, la variable $mensaje se rellena con un texto de éxito o de error. Además, la variable $clase_mensaje guarda el nombre de una clase CSS ("exito" o "error").

    4. Visualización Dinámica: En la parte final del HTML, el último bloque de PHP comprueba si la variable $mensaje tiene contenido. Si lo tiene, imprime un párrafo en pantalla. Crucialmente, utiliza la variable $clase_mensaje para asignarle una clase al párrafo (<p class="exito"> o <p class="error">), lo que permite que el mensaje se muestre en verde o en rojo, dando una retroalimentación visual clara al usuario.

    Tratamiento de Ficheros con Formularios

    Permitir que los usuarios suban ficheros es una funcionalidad clave en innumerables aplicaciones web, desde subir una foto de perfil en una red social hasta adjuntar un documento en un sistema de soporte. El proceso involucra una configuración especial en el formulario HTML y una gestión cuidadosa de los datos en el script de PHP.

    Para que un formulario pueda enviar ficheros, debe cumplir tres requisitos obligatorios:

    1. El method debe ser POST. No es posible subir ficheros con GET.
    2. La etiqueta <form> debe incluir el atributo enctype="multipart/form-data". Este atributo le indica al navegador que debe codificar los datos del formulario de una manera especial que permite incluir el contenido de los ficheros. Sin esto, no funcionará.
    3. Se debe usar el campo de entrada <input type="file">, que mostrará al usuario un botón para seleccionar un fichero de su dispositivo.
    <!DOCTYPE html>
<html lang="es">
    <head>
        <meta charset="UTF-8">
        <title>Subida de Ficheros</title>
    </head>
    <body>
        <h2>Sube tu foto de perfil</h2>
        <form action="procesar_upload.php" method="post" enctype="multipart/form-data">
            <label for="fichero">Selecciona un fichero:</label>
            <input type="file" id="fichero" name="fichero_usuario">
            <br><br>
            <button type="submit">Subir Fichero</button>
        </form>
    </body>
</html>

    Cuando se envía un formulario con un fichero, la información de dicho fichero no está en $_POST. En su lugar, PHP la pone a nuestra disposición en la variable superglobal $_FILES.

    $_FILES es un array asociativo que contiene información detallada sobre cada fichero subido. Si nuestro <input> se llamaba name="fichero_usuario", podremos acceder a sus datos a través de $_FILES['fichero_usuario']. Esta variable será, a su vez, un array con las siguientes claves:

    • ['name']: El nombre original del fichero en el ordenador del cliente (p. ej., mi_foto.jpg).
    • ['type']: El tipo MIME del fichero (p. ej., image/jpeg).
    • ['size']: El tamaño del fichero en bytes.
    • ['tmp_name']: La ubicación temporal donde el servidor ha guardado el fichero subido. Este es el dato más importante, ya que es la ruta real del fichero en el servidor.
    • ['error']: Un código de error. Si el valor es 0 (o la constante UPLOAD_ERR_OK), la subida se ha realizado sin problemas.

    El flujo de trabajo en el script PHP es siempre el mismo: comprobar, validar y mover.

    <?php
    // Comprobamos si se ha enviado el formulario y si se ha subido un fichero.
    if ($_SERVER['REQUEST_METHOD'] == 'POST' && isset($_FILES['fichero_usuario'])) {

        $fichero = $_FILES['fichero_usuario'];

        // 1. Comprobamos si hubo algún error en la subida.
        if ($fichero['error'] === UPLOAD_ERR_OK) {

            // 2. VALIDACIÓN (¡MUY IMPORTANTE!)
            $tamaño_maximo = 2 * 1024 * 1024; // 2 MB
            $tipos_permitidos = ['image/jpeg', 'image/png'];

            if ($fichero['size'] > $tamaño_maximo) {
                die("Error: El fichero es demasiado grande. Máximo 2 MB.");
            }

            if (!in_array($fichero['type'], $tipos_permitidos)) {
                die("Error: Tipo de fichero no permitido. Solo se aceptan JPG y PNG.");
            }

            // 3. MOVER el fichero de la carpeta temporal a la definitiva.
            $carpeta_destino = 'uploads/';
            // Creamos un nombre de fichero único para evitar sobreescribir archivos.
            $nombre_fichero_nuevo = uniqid() . '-' . basename($fichero['name']);
            $ruta_definitiva = $carpeta_destino . $nombre_fichero_nuevo;

            // move_uploaded_file() es la función segura de PHP para esto.
            if (move_uploaded_file($fichero['tmp_name'], $ruta_definitiva)) {
                echo "<h1>¡Fichero subido con éxito!</h1>";
                echo "<p>El fichero se ha guardado en: " . $ruta_definitiva . "</p>";
            } else {
                echo "Error: No se pudo mover el fichero subido.";
            }

        } else {
            echo "Error en la subida del fichero. Código: " . $fichero['error'];
        }
    }
?>

    Consideraciones de Seguridad Fundamentales

    Gestionar la subida de ficheros es una de las áreas más críticas en cuanto a seguridad:

    • Nunca confíes en los datos del cliente: No confíes en $_FILES['fichero_usuario']['name'] ni en ['type']. Un atacante puede manipular estos datos fácilmente. Utiliza validaciones en el servidor para comprobar el tamaño y, si es posible, el contenido real del fichero.
    • Crea nombres de fichero seguros: Nunca uses el nombre original del fichero directamente para guardarlo en tu servidor. Podría contener caracteres maliciosos (../) o sobreescribir un fichero existente. Genera siempre un nombre único y seguro, como hemos hecho con uniqid().
    • Permisos de la carpeta: La carpeta de destino (uploads/ en nuestro ejemplo) debe tener los permisos de escritura correctos para que el servidor web pueda guardar ficheros en ella.
    • Ubicación de la carpeta: No guardes ficheros ejecutables (como .php) en una carpeta de subida, y considera si la carpeta debe estar dentro o fuera del directorio raíz accesible desde la web, dependiendo de si los ficheros deben ser accesibles directamente por URL o no.

    Validación Avanzada del Lado del Servidor

    Mientras que la validación básica (como verificar que los campos no estén vacíos o el tipo MIME de un archivo) es esencial, la validación avanzada del lado del servidor es crucial para construir aplicaciones robustas, seguras y profesionales. Esta etapa va más allá de las comprobaciones superficiales, centrándose en la estructura de los datos, la centralización de la lógica de validación y una retroalimentación de errores precisa al usuario.

    Validación Estructurada: Centralización de la Lógica

    La validación nunca debe realizarse de manera dispersa dentro de los scripts que procesan los formularios. En cambio, se debe implementar una validación estructurada mediante una función o una clase dedicada.

    <?php

class SimpleValidator {
    protected $data;
    protected $rules;
    protected $errors = [];

    public function __construct(array $data, array $rules) {
        $this->data = $data;
        $this->rules = $rules;
    }

    /**
     * Ejecuta todas las reglas definidas y devuelve true si es válido, false si hay errores.
     */
    public function validate(): bool {
        //Cada regla la separamos como un elemento clave => valor.
        foreach ($this->rules as $field => $rulesString) {
            $rules = explode('|', $rulesString);
            $value = $this->data[$field] ?? null;

            foreach ($rules as $rule) {
                // Aquí se implementaría la lógica para cada regla (required, email, min:5, etc.)

                if ($rule === 'required' && empty($value)) {
                    $this->addError($field, "El campo {$field} es obligatorio.");
                    continue;
                }

                //Validamos que el email es correcto. FILTER_VALIDATE_EMAIL viene predefinido en php.
                if ($rule === 'email' && !filter_var($value, FILTER_VALIDATE_EMAIL)) {
                    $this->addError($field, "El formato del campo {$field} no es válido.");
                    continue;
                }

                // Ejemplo simple de regex para contraseña (simula complejidad mínima)
                if ($rule === 'password_strong' && !preg_match('/[A-Z]/', $value)) {
                     $this->addError($field, "La contraseña debe contener al menos una mayúscula.");
                     continue;
                }
            }
        }

        return empty($this->errors);
    }

    /**
     * Añade un error al array si aún no existe para ese campo.
     */
    protected function addError(string $field, string $message): void {
        if (!isset($this->errors[$field])) {
            $this->errors[$field] = $message;
        }
    }

    /**
     * Devuelve el array de errores.
     */
    public function getErrors(): array {
        return $this->errors;
    }
}
?>

    Al centralizar la lógica de validación se consigue un código más limpio y fácil de mantener. En lugar de tener sentencias if y checks repartidos, se crea un único punto de entrada (por ejemplo, una clase Validator o una función validate_form(array $data, array $rules)) que recibe todos los datos de entrada ($_POST) y un conjunto de reglas ($rules). Este validador se encarga de ejecutar todas las comprobaciones necesarias y devolver un array de errores, si los hay. Esto no solo mejora la reutilización del código (puedes validar diferentes formularios usando la misma clase), sino que también asegura que las reglas de negocio críticas se apliquen de forma consistente en toda la aplicación.

    Veamos un ejemplo de uso de la clase definida anteriormente:

    <?php
    // Incluimos nuestra clase validadora
    require 'SimpleValidator.php'; 

    // 1. Datos del formulario (En un escenario real, esto sería $_POST)
    $data = [
        'username' => 'usuario123',
        'email' => 'correo-invalido', // Este dato fallará la validación
        'password' => 'pass', 
    ];

    // 2. Definición de Reglas (El contrato de validación)
    $rules = [
        'username' => 'required',
        'email' => 'required|email',
        'password' => 'required|password_strong', 
    ];

    // 3. Centralización de la Lógica: Instanciar y Validar
    $validator = new SimpleValidator($data, $rules);

    if ($validator->validate()) {
        // Si es VÁLIDO: Procesar los datos (guardar en BD, enviar email, etc.)
        echo "¡Validación exitosa! Datos listos para ser procesados.";

    } else {
        // Si NO es VÁLIDO: Obtener los errores y enviarlos de vuelta al formulario.
        $validation_errors = $validator->getErrors();

        echo "<h2>Errores de Validación Encontrados:</h2>";
        echo "<pre>";
        print_r($validation_errors);
        echo "</pre>";

        /* En un entorno web real, aquí se guardaría $data (datos de entrada) y
        $validation_errors (errores) en la sesión, y se redirigiría al usuario
        al formulario para mostrar los errores y los datos ingresados.
        */
    }
?>

    Uso de Expresiones Regulares

    Las Expresiones Regulares (Regex) son patrones de búsqueda que permiten realizar una validación de estructura profunda que va más allá de las funciones básicas. PHP soporta Regex mediante las funciones de la familia preg_*.

    El uso de Regex es indispensable para validar formatos específicos:

    • Emails: Asegurar que la estructura del correo cumpla con el formato estándar (usuario@dominio.tld).
    • Contraseñas Fuertes: Imponer requisitos de seguridad complejos (por ejemplo, que contenga al menos una mayúscula, un número y un símbolo).
    • Números de Teléfono/Códigos Postales: Verificar que se ajusten a patrones regionales específicos.

    Aunque PHP ya ofrece funciones integradas para algunos casos (como filter_var($email, FILTER_VALIDATE_EMAIL)), las expresiones regulares ofrecen la flexibilidad de definir patrones de seguridad personalizados.

    <?php
    $password = "P4ssw0rd!";
    // Patrón: Al menos 8 caracteres, una mayúscula, una minúscula, un número y un símbolo.
    $regex_password = '/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[^a-zA-Z\d\s]).{8,}$/';

    if (!preg_match($regex_password, $password)) {
        // El error de validación debe ser registrado y devuelto.
        $errores['password'] = "La contraseña debe tener al menos 8 caracteres, una mayúscula, un número y un símbolo.";
    }
?>

    Retroalimentación Precisa de Errores

    Un aspecto fundamental de la validación avanzada es la experiencia del usuario. Cuando la validación falla, los errores no deben mostrarse como una lista genérica, sino que deben estar asociados al campo específico que causó el problema.

    Para lograr esto, el array de errores devuelto por la clase de validación debe usar el nombre del campo como clave. Por ejemplo, la clase Validator devuelve un array: ['email' => 'El formato es incorrecto', 'password' => 'Demasiado corta'].

    Tras el error, el script de procesamiento debe redirigir al formulario, inyectando el array de errores y, crucialmente, los datos originales ingresados por el usuario (excluyendo contraseñas) para que no tenga que rellenar todo el formulario de nuevo.

    Por último, en el formulario HTML, el código embebido verifica si existe un error específico para ese campo, y lo muestra justo debajo del <input>.

    <label for="email">Correo Electrónico:</label>
<input type="email" name="email" value="<?= e($old_input['email'] ?? '') ?>">

<?php if (isset($errores['email'])): ?>
    <p style="color: red;"><?= e($errores['email']) ?></p>
<?php endif; ?>

    Al implementar estas técnicas, la aplicación no solo garantiza que los datos sean correctos, sino que también ofrece una experiencia de usuario profesional, guiándolos de manera clara para corregir los errores de entrada.
