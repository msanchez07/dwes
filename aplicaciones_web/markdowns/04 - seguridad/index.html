    Seguridad

    Una vez que nuestra aplicación es capaz de utilizar sesiones de usuario, debemos establecer los mecanismos de seguridad encargados de establecer estase sesiones. Además, no todos los usuarios deben tener acceso a toda la información ni a todas las funcionalidades. Es fundamental establecer un sistema que controle quién puede entrar en nuestra aplicación y qué puede hacer una vez dentro. Este apartado se centra en dos conceptos clave que a menudo se confunden, pero que son distintos y complementarios: la autenticación y la autorización.

    La autenticación es el proceso de verificar la identidad de un usuario. Responde a la pregunta: "¿Quién eres?". El ejemplo más común es el formulario de inicio de sesión, donde un usuario proporciona un nombre y una contraseña para demostrar que es quien dice ser. Si las credenciales son correctas, el usuario está autenticado.

    La autorización, por otro lado, es el proceso que tiene lugar después de la autenticación. Responde a la pregunta: "¿Qué tienes permiso para hacer?". Una vez que sabemos quién es el usuario, el sistema de autorización comprueba si tiene los privilegios necesarios para realizar una acción específica, como acceder a un panel de administración, borrar un producto o editar el perfil de otro usuario.

    Para gestionar la autorización de forma eficiente, se utiliza un modelo basado en usuarios, roles y permisos. Un usuario es la entidad individual que se autentica. Un permiso es una acción específica (p. ej., "editar-articulo"). Un rol (como "Administrador", "Editor" o "Suscriptor") es un conjunto de permisos. En lugar de asignar permisos uno por uno a cada usuario, le asignamos un rol, lo que simplifica enormemente la gestión. En las siguientes secciones, exploraremos cómo implementar estos sistemas en nuestra aplicación PHP.

    Autenticación

    La autenticación es el proceso de confirmar la identidad de un usuario. En la práctica, esto se traduce en un sistema de inicio de sesión. Vamos a construir un ejemplo funcional y seguro que abarca el ciclo completo: el formulario de login, el procesamiento de las credenciales, la protección de una página privada y el cierre de sesión.

    Para este ejemplo, simularemos una base de datos con un array de usuarios para centrarnos exclusivamente en el flujo de autenticación, que se basa en el uso de sesiones.

    La Estructura de Ficheros

    Nuestra aplicación se compondrá de los siguientes ficheros:

    • login.php: Muestra el formulario de inicio de sesión y los mensajes de error.
    • procesar_login.php: Valida las credenciales y gestiona la sesión.
    • privado.php: Una página de contenido restringido, solo para usuarios autenticados.
    • logout.php: Destruye la sesión para cerrar la sesión del usuario.

    Este flujo completo —formulario, procesamiento, redirección, protección de página y cierre de sesión— es la base de cualquier sistema de autenticación en PHP.

    El Formulario de Inicio de Sesión (login.php)

    Este fichero muestra el formulario y, muy importante, inicia una sesión para poder mostrar mensajes de error que le envíe el script de procesamiento.

    <?php
    // Siempre iniciar la sesión al principio de todo
    session_start();
?>
<!DOCTYPE html>
<html lang="es">
    <head>
        <meta charset="UTF-8">
        <title>Iniciar Sesión</title>
    </head>
    <body>
        <h2>Acceso de Usuario</h2>

        <?php
        // Si existe un mensaje de error en la sesión, lo mostramos
        if (isset($_SESSION['error_login'])) {
            echo '<p style="color:red;">' . $_SESSION['error_login'] . '</p>';
            // Una vez mostrado, lo eliminamos para que no vuelva a aparecer
            unset($_SESSION['error_login']);
        }
        ?>

        <form action="procesar_login.php" method="post">
            Usuario: <input type="text" name="usuario"><br>
            Contraseña: <input type="password" name="password"><br>
            <button type="submit">Entrar</button>
        </form>
    </body>
</html>

    El Procesador de Datos (procesar_login.php)

    Este es el cerebro del sistema. Busca al usuario, verifica su contraseña y redirige a la página correspondiente.

    <?php
    session_start();

    // Simulamos una base de datos de usuarios
    // La contraseña para 'admin' es '1234', hasheada previamente con password_hash('1234', PASSWORD_DEFAULT)
    $usuarios = [
        'admin' => [
            'id' => 1,
            'password_hash' => '$2y$10$GLJg.PF/b0..y.Yk92d3A.29Jc5Qd3Y.E2rJ/NnKb.p2j/i5g7Ua.' 
        ]
    ];

    // Recuperamos los datos del formulario
    $usuario_form = $_POST['usuario'];
    $password_form = $_POST['password'];

    // Verificamos si el usuario existe
    if (isset($usuarios[$usuario_form])) {
        $usuario_db = $usuarios[$usuario_form];

        // Verificamos la contraseña
        if (password_verify($password_form, $usuario_db['password_hash'])) {
            // Si la contraseña es correcta, guardamos el ID del usuario en la sesión
            $_SESSION['usuario_id'] = $usuario_db['id'];

            // Redirigimos a la página privada
            header('Location: privado.php');
            exit(); // Es importante terminar el script después de una redirección
        }
    }

    // Si llegamos aquí, es que el usuario o la contraseña son incorrectos
    // Guardamos un mensaje de error en la sesión
    $_SESSION['error_login'] = "Usuario o contraseña incorrectos.";

    // Redirigimos de vuelta al formulario de login
    header('Location: login.php');
    exit();
?>

    La Página Protegida (privado.php)

    Esta página solo debe ser accesible para usuarios que hayan iniciado sesión correctamente. Para asegurarlo, lo primero que hace es comprobar si existe la variable de sesión que creamos en el paso anterior.

    <?php
    session_start();

    // Comprobamos si el usuario está autenticado
    if (!isset($_SESSION['usuario_id'])) {
        // Si no ha iniciado sesión, lo redirigimos al login
        header('Location: login.php');
        exit();
    }

    // Si la sesión existe, mostramos el contenido privado
?>
<!DOCTYPE html>
<html lang="es">
    <head>
        <title>Página Privada</title>
    </head>
    <body>
        <h1>Bienvenido a la Zona Privada</h1>
        <p>Este contenido es secreto y solo para usuarios autenticados.</p>
        <p>Tu ID de usuario es: <?php echo $_SESSION['usuario_id']; ?></p>
        <a href="logout.php">Cerrar Sesión</a>
    </body>
</html>

    El Cierre de Sesión (logout.php)

    Este script simplemente destruye la sesión y redirige al usuario a la página de login.

    <?php
    session_start();

    // Borra todas las variables de la sesión
    session_unset();

    // Destruye la sesión
    session_destroy();

    // Redirige al login
    header('Location: login.php');
    exit();
?>

    Autorización Basada en Roles

    La autorización es el proceso de conceder o denegar permisos para acceder a ciertos recursos o realizar ciertas acciones. El método más común para gestionarla es a través de roles. Un rol (p. ej., "administrador", "editor", "lector") es una etiqueta que agrupa un conjunto de permisos.

    Vamos a expandir nuestro ejemplo de login anterior para implementar un sistema de roles simple. Tendremos dos roles: editor y lector. Solo los editores podrán ver un botón especial para "Editar Contenido".

    Primero, añadimos un campo rol a nuestro array de usuarios.

    <?php
    // Simulamos una base de datos de usuarios
    $usuarios = [
        'admin' => [
            'id' => 1,
            'password_hash' => '$2y$10$GLJg.PF/b0..y.Yk92d3A.29Jc5Qd3Y.E2rJ/NnKb.p2j/i5g7Ua.', // Contraseña: 1234
            'rol' => 'editor' // Rol de administrador
        ],
        'ana' => [
            'id' => 2,
            'password_hash' => '$2y$10$S.G7Iz22x5P5pwc2/g8VgeBAd2/GfVb2prE2D123d.g4s5H6i7J8k.', // Contraseña: password
            'rol' => 'lector' // Rol de lector
        ]
    ];
?>

    Ahora, cuando un usuario inicie sesión correctamente, debemos guardar también su rol en la sesión.

    <?php
    // En procesar_login.php, dentro del if (password_verify(...))

    if (password_verify($password_form, $usuario_db['password_hash'])) {
        // Si la contraseña es correcta, guardamos los datos en la sesión
        $_SESSION['usuario_id'] = $usuario_db['id'];
        $_SESSION['rol'] = $usuario_db['rol']; // <-- LÍNEA AÑADIDA

        // Redirigimos a la página privada
        header('Location: privado.php');
        exit();
    }
?>

    Ahora que tenemos el rol del usuario en la sesión ($_SESSION['rol']), podemos usarlo en nuestras páginas protegidas para mostrar u ocultar contenido.

    <?php
    session_start();

    // Comprobamos si el usuario está autenticado (esto no cambia)
    if (!isset($_SESSION['usuario_id'])) {
        header('Location: login.php');
        exit();
    }

    // Si la sesión existe, mostramos el contenido...
?>
<!DOCTYPE html>
<html lang="es">
    <head>
        <title>Página Privada</title>
    </head>
    <body>
        <h1>Bienvenido a la Zona Privada</h1>
        <p>Este contenido es secreto y solo para usuarios autenticados.</p>
        <p>Tu rol es: <strong><?php echo htmlspecialchars($_SESSION['rol']); ?></strong></p>

        <hr>

        <?php
            // --- AQUÍ EMPIEZA LA LÓGICA DE AUTORIZACIÓN ---
            // Comprobamos si el rol del usuario guardado en la sesión es 'editor'.
            if ($_SESSION['rol'] === 'editor') {
                echo '<p><strong>Panel de Administración:</strong></p>';
                echo '<button>Editar Contenido</button>';
            }
        ?>

        <hr>
        <a href="logout.php">Cerrar Sesión</a>
    </body>
</html>

    El flujo de autorización comienza en el momento del inicio de sesión. Cuando un usuario como admin proporciona las credenciales correctas, el script procesar_login.php no solo lo autentica guardando su ID en la sesión, sino que también almacena su rol, en este caso, 'editor'. Al ser redirigido a la página privado.php, el script primero verifica que el usuario está autenticado y luego procede a la comprobación de rol. La condición if ($_SESSION['rol'] === 'editor') se evalúa como verdadera, por lo que se le muestra el contenido privilegiado, como el "Panel de Administración" y el botón para editar.

    Este comportamiento contrasta con el de la usuaria ana, cuyo rol de 'lector' haría que la misma condición se evaluara como falsa, ocultándole así las secciones de la página que no tiene permiso para ver. Este es el principio fundamental de la autorización basada en roles: al almacenar el rol del usuario en la sesión, podemos implementar fácilmente reglas de acceso granulares en cualquier parte de nuestra aplicación para controlar quién puede ver y hacer qué.
