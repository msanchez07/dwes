    Bases de datos

    En el apartado anterior, exploramos cómo guardar información de forma permanente utilizando ficheros. Si bien este método es útil para aplicaciones simples, registros (logs) o configuraciones, presenta serias limitaciones a medida que un proyecto crece. ¿Qué ocurre si dos usuarios intentan escribir en el mismo fichero a la vez? ¿Cómo realizamos búsquedas complejas y eficientes sin tener que leer un fichero gigante en memoria? ¿Cómo gestionamos las relaciones entre diferentes tipos de datos, como usuarios y sus pedidos?

    Para resolver estos desafíos, la industria del software utiliza Sistemas Gestores de Bases de Datos (SGBD o DBMS en inglés). Un SGBD es un software altamente especializado cuyo único propósito es almacenar, gestionar y recuperar grandes volúmenes de datos de forma segura, eficiente y concurrente. Son la columna vertebral de prácticamente todas las aplicaciones web modernas.

    La mayoría de las bases de datos utilizadas en el desarrollo web son bases de datos relacionales. Este modelo organiza los datos en tablas estructuradas, compuestas por filas (registros) y columnas (campos). Para comunicarnos con la base de datos, utilizamos un lenguaje estándar llamado SQL (Structured Query Language), que nos permite definir la estructura de nuestros datos y realizar operaciones sobre ellos.

    En este capítulo, daremos el paso definitivo en la persistencia de datos. Aprenderemos cómo conectar nuestra aplicación PHP a una base de datos MySQL (uno de los SGBD más populares del mundo), cómo ejecutar consultas SQL para crear, leer, actualizar y borrar datos, y cómo integrar esta información en nuestras páginas web dinámicas.

    MySQL

    Para que nuestra aplicación PHP pueda comunicarse con un servidor de bases de datos MySQL, primero debe establecer una conexión. PHP ofrece varias formas de hacerlo, pero el método moderno, seguro y recomendado es utilizar la extensión PDO (PHP Data Objects).

    PDO es una capa de abstracción de acceso a datos, lo que significa que nos proporciona un conjunto de funciones consistente para hablar con diferentes tipos de bases de datos (MySQL, PostgreSQL, SQLite, etc.). Esto hace que nuestro código sea más portable. Su principal ventaja es su excelente soporte para sentencias preparadas, que es la técnica fundamental para prevenir ataques de inyección SQL.

    Para establecer una conexión exitosa con una base de datos, nuestra aplicación necesita presentar las credenciales correctas, de forma muy similar a como un usuario necesita una llave y una dirección para entrar en una casa. Estos cuatro datos son indispensables.

    El primero es el Host o servidor, que es la dirección de red de la máquina donde se está ejecutando el sistema gestor de bases de datos. En un entorno de desarrollo local, este valor es casi siempre localhost o 127.0.0.1, que apunta a la propia máquina. Una vez localizado el servidor, debemos especificar el Nombre de la Base de Datos, ya que un mismo servidor puede alojar múltiples bases de datos para diferentes aplicaciones. Finalmente, para la autenticación, debemos proporcionar el Usuario y la Contraseña que han sido configurados con los permisos necesarios para acceder y operar sobre esa base de datos específica.

    <?php
    // 1. Datos de conexión
    $host = 'localhost';
    $dbname = 'mi_tienda';
    $usuario = 'root';
    $contraseña = 'tu_contraseña_secreta'; // Reemplazar con tu contraseña

    try {
        // 2. Crear la conexión PDO

        // El DSN (Data Source Name) es una cadena que especifica el tipo de BBDD,
        // el host y el nombre de la base de datos.
        $dsn = "mysql:host=$host;dbname=$dbname;charset=utf8mb4";

        // Opciones de PDO para la conexión.
        $opciones = [
            PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION, // Lanza excepciones en errores
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,       // Devuelve los resultados como arrays asociativos
            PDO::ATTR_EMULATE_PREPARES   => false,                  // Desactiva la emulación de sentencias preparadas
        ];

        // Creamos la instancia de PDO. La variable $pdo contendrá el objeto de conexión.
        $pdo = new PDO($dsn, $usuario, $contraseña, $opciones);

        // Si llegamos aquí, la conexión fue exitosa.
        // En una aplicación real, no mostraríamos este mensaje.
        // echo "Conexión a la base de datos '$dbname' establecida con éxito.";

    } catch (PDOException $e) {
        // Si algo sale mal, se captura la excepción.
        // En producción, no deberíamos mostrar los detalles del error al usuario.
        // En su lugar, lo registraríamos en un fichero de log.
        echo "Error al conectar con la base de datos: " . $e->getMessage();
        die(); // Detenemos la ejecución del script.
    }

    // A partir de aquí, la variable $pdo está disponible para ser usada en otros scripts.
?>

    Observa la cadena mysql:host=..., que es específica para MySQL. Si quisiéramos conectar a PostgreSQL, cambiaría a pgsql:host=.... Por otro lado, el charset=utf8mb4 es muy importante para asegurar que los caracteres especiales (como acentos o emojis) se manejen correctamente.

    Por otro lado, la opción PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION es crucial. Le dice a PDO que, en lugar de generar un Warning, debe lanzar una PDOException si algo falla. Esto nos permite capturar el error con el bloque catch y manejarlo de forma controlada.

    Hay que tener en cuenta que el código anterior es perfecto para guardarlo en un fichero llamado conexion.php o similar. Luego, en cualquier otro script donde necesites acceder a la base de datos, simplemente tienes que incluir este fichero al principio con require_once 'conexion.php'; y la variable $pdo estará lista para ser utilizada.

    Una vez visto como se crea una nueva conexión, ahora nos centraremos en la consulta, inserción, modificación y eliminación de los datos.

    Consultar datos

    Una vez que tenemos nuestro objeto de conexión en la variable $pdo, podemos utilizarlo para enviar consultas a la base de datos. Sin embargo, antes de ver el método correcto, es absolutamente crucial entender el principal riesgo de seguridad en las aplicaciones web: la inyección SQL.

    Un error de principiante sería construir una consulta insertando variables directamente en el string de SQL, así: $sql = "SELECT * FROM usuarios WHERE id = $id_usuario"; // ¡INCORRECTO Y PELIGROSO!

    Si un atacante lograra manipular el valor de $id_usuario, podría "inyectar" código SQL malicioso y corromper o robar toda tu base de datos. Por esta razón, nunca debes insertar variables directamente en una consulta. La forma correcta y segura de ejecutar consultas es mediante sentencias preparadas (prepared statements). Es un proceso de dos pasos que separa la consulta (la instrucción) de los datos (los parámetros).

    El proceso de una sentencia preparada se divide en dos fases distintas, una separación que es la clave de su seguridad y eficiencia. En la primera fase, la de preparación, la aplicación no envía los datos del usuario, sino únicamente la plantilla de la consulta SQL al servidor de la base de datos. Esta plantilla contiene marcadores de posición (como ? o :nombre) en lugar de los valores reales. Al recibir esta estructura, el motor de la base de datos la analiza, comprueba su sintaxis y compila un plan de ejecución optimizado, dejando huecos donde irán los datos.

    La segunda fase es la de ejecución. En este paso, la aplicación envía los valores de los parámetros por separado. El servidor de la base de datos, que ya tiene la estructura de la consulta pre-compilada y validada, simplemente toma estos valores y los inserta de forma segura en los espacios reservados, tratándolos siempre como datos literales y nunca como parte del código SQL. Esta estricta separación entre la instrucción y los datos garantiza que un atacante no pueda "inyectar" código malicioso, ya que su entrada nunca será interpretada como un comando.

    Este método es inmune a la inyección SQL porque los datos de los parámetros nunca se interpretan como código SQL; siempre se tratan como valores literales. Veamos un ejemplo de obtención de un único registro, cuyo proceso se basa en utilizar el método fetch() (por ejemplo, al buscar un usuario por su ID único):

    <?php
    // 1. Incluimos nuestro fichero de conexión.
    require_once 'conexion.php';

    $id_usuario_a_buscar = 1;

    try {
        // 2. Preparamos la consulta SQL con un marcador de posición nombrado (:id).
        $sql = "SELECT id, nombre, email FROM usuarios WHERE id = :id";
        $stmt = $pdo->prepare($sql);

        // 3. Ejecutamos la consulta, pasando los parámetros en un array.
        // La clave del array debe coincidir con el nombre del marcador.
        $stmt->execute([':id' => $id_usuario_a_buscar]);

        // 4. Obtenemos el resultado. fetch() devuelve una fila.
        $usuario = $stmt->fetch();

        // 5. Mostramos los datos.
        if ($usuario) {
            echo "<h1>Datos del Usuario</h1>";
            echo "ID: " . $usuario['id'] . "<br>";
            echo "Nombre: " . $usuario['nombre'] . "<br>";
            echo "Email: " . $usuario['email'] . "<br>";
        } else {
            echo "No se encontró ningún usuario con el ID " . $id_usuario_a_buscar;
        }

    } catch (PDOException $e) {
        die("Error al realizar la consulta: " . $e->getMessage());
    }
?>

    En caso de que necesitemos recuperar más de un resultado, vamos a utilizar el método fetchAll() (por ejemplo, todos los productos de una categoría). fetchAll() devuelve un array multidimensional con todos los resultados.

    <?php
    require_once 'conexion.php';

    $categoria_a_buscar = "electrónica";

    try {
        // 2. Preparamos la consulta.
        $sql = "SELECT nombre, precio FROM productos WHERE categoria = :categoria ORDER BY nombre ASC";
        $stmt = $pdo->prepare($sql);

        // 3. Ejecutamos.
        $stmt->execute([':categoria' => $categoria_a_buscar]);

        // 4. Obtenemos TODOS los resultados en un array.
        $productos = $stmt->fetchAll();

        // 5. Mostramos los datos.
        if ($productos) {
            echo "<h1>Productos de la categoría: " . ucfirst($categoria_a_buscar) . "</h1>";
            echo "<ul>";
            foreach ($productos as $producto) {
                echo "<li>" . $producto['nombre'] . " - " . $producto['precio'] . " €</li>";
            }
            echo "</ul>";
        } else {
            echo "No se encontraron productos en la categoría " . $categoria_a_buscar;
        }

    } catch (PDOException $e) {
        die("Error al realizar la consulta: " . $e->getMessage());
    }
?>

    Insertar nuevos datos

    La inserción de nuevos registros es la operación que nos permite añadir datos a nuestra base de datos, por ejemplo, cuando un nuevo usuario se registra o cuando se publica un nuevo producto. Esta operación se realiza con la sentencia INSERT de SQL. Dado que los datos a insertar casi siempre provienen de una fuente externa (como un formulario rellenado por un usuario), es absolutamente obligatorio utilizar sentencias preparadas para prevenir la inyección SQL.

    El proceso es muy similar al que vimos para las consultas SELECT: preparamos una plantilla de la consulta con marcadores de posición y luego la ejecutamos pasándole los datos de forma segura.

    Imaginemos que hemos recibido los datos de un formulario de registro. El siguiente script se encargaría de insertar un nuevo usuario en la tabla usuarios.

    insertar_usuario.php 

    <?php
    // 1. Incluimos el fichero de conexión.
    require_once 'conexion.php';

    // 2. Datos del nuevo usuario (estos vendrían de un $_POST en un caso real).
    $nombre = "Carlos Ruiz";
    $email = "carlos.ruiz@email.com";
    $password_texto_plano = "secreto123";

    // ¡IMPORTANTE! Nunca guardes contraseñas en texto plano.
    // Usa password_hash() para crear un hash seguro.
    $password_hasheada = password_hash($password_texto_plano, PASSWORD_DEFAULT);

    try {
        // 3. Preparamos la consulta SQL de inserción.
        // Usamos marcadores de posición nombrados para cada valor.
        $sql = "INSERT INTO usuarios (nombre, email, password) VALUES (:nombre, :email, :password)";
        $stmt = $pdo->prepare($sql);

        // 4. Ejecutamos la consulta, pasando los datos en un array asociativo.
        $stmt->execute([
            ':nombre' => $nombre,
            ':email' => $email,
            ':password' => $password_hasheada
        ]);

        // 5. Comprobamos si la inserción fue exitosa y obtenemos el ID.
        $filas_afectadas = $stmt->rowCount();

        if ($filas_afectadas > 0) {
            $nuevo_id = $pdo->lastInsertId();
            echo "¡Usuario registrado con éxito! Su nuevo ID es: " . $nuevo_id;
        } else {
            echo "Error: No se pudo insertar el registro.";
        }

    } catch (PDOException $e) {
        // Manejo de errores (p. ej., un email duplicado).
        die("Error al insertar el usuario: " . $e->getMessage());
    }
?>

    Una vez que se ejecuta una sentencia de modificación de datos como INSERT, UPDATE o DELETE, es fundamental verificar si la operación tuvo el efecto esperado. Para ello, el objeto statement nos proporciona el método rowCount(), que devuelve el número exacto de filas que fueron afectadas por la consulta. En el caso de una inserción, esperaríamos que este valor fuera 1, lo que nos da una confirmación fiable de que el nuevo registro se ha añadido correctamente a la base de datos.

    Tras confirmar la creación de un nuevo registro, a menudo surge una necesidad inmediata: conocer el identificador único que la base de datos le ha asignado, especialmente si la tabla utiliza una clave primaria con AUTO_INCREMENT. Para esta tarea, el objeto de conexión ($pdo) nos ofrece el método lastInsertId(). Al llamarlo inmediatamente después de una inserción exitosa, nos devolverá el ID del registro recién creado, un dato fundamental para operaciones posteriores, como redirigir al usuario a la página de su nuevo perfil.

    Finalmente, al hablar de la inserción de datos de usuario, es ineludible abordar una práctica de seguridad no negociable que precede a la propia consulta. Las contraseñas nunca deben guardarse en texto plano. Para ello, PHP proporciona la función password_hash(), que convierte la contraseña en un "hash" criptográfico seguro e irreversible. Este hash es lo que se almacena en la base de datos. Posteriormente, para verificar un inicio de sesión, se utiliza la función password_verify(), que compara de forma segura la contraseña introducida por el usuario con el hash almacenado, sin necesidad de revertir el proceso.

    Modificar datos

    La actualización de registros es una de las operaciones más comunes en cualquier aplicación. Se utiliza para modificar datos que ya existen en la base de datos, como cuando un usuario cambia su dirección de correo electrónico o se actualiza el stock de un producto. La sentencia SQL para esta tarea es UPDATE.

    Al igual que con la inserción, los datos para la actualización suelen provenir del usuario, por lo que el uso de sentencias preparadas es obligatorio para garantizar la seguridad. Además, en una consulta UPDATE, la cláusula WHERE es de vital importancia, ya que especifica qué registro o registros deben ser modificados. Omitir la cláusula WHERE resultaría en la actualización de todas las filas de la tabla.

    <?php
    // 1. Incluimos el fichero de conexión.
    require_once 'conexion.php';

    // 2. Datos para la actualización (vendrían de un formulario).
    $id_usuario_a_modificar = 1;
    $nuevo_email = "ana.garcia.nuevo@email.com";

    try {
        // 3. Preparamos la consulta SQL de actualización.
        // Se especifican las columnas a cambiar en SET y el registro a modificar en WHERE.
        $sql = "UPDATE usuarios SET email = :email WHERE id = :id";
        $stmt = $pdo->prepare($sql);

        // 4. Ejecutamos la consulta, pasando un array con los nuevos datos y el ID.
        $stmt->execute([
            ':email' => $nuevo_email,
            ':id'    => $id_usuario_a_modificar
        ]);

        // 5. Verificamos el resultado con rowCount().
        $filas_afectadas = $stmt->rowCount();

        if ($filas_afectadas > 0) {
            echo "¡El email del usuario con ID $id_usuario_a_modificar ha sido actualizado con éxito!";
        } else {
            echo "No se encontró ningún usuario con el ID $id_usuario_a_modificar o el email ya era el mismo.";
        }

    } catch (PDOException $e) {
        die("Error al actualizar el registro: " . $e->getMessage());
    }
?>

    Al ejecutar una sentencia UPDATE, la cláusula WHERE es el componente de mayor importancia estratégica. Esta cláusula define la condición precisa que debe cumplir un registro para ser objeto de la modificación. En nuestro ejemplo, WHERE id = :id actúa como un filtro de alta precisión, garantizando que la operación de escritura afecte única y exclusivamente al usuario con ese identificador. Omitir o definir incorrectamente esta cláusula es uno de los errores más peligrosos en SQL, ya que podría resultar en la modificación no intencionada de miles o incluso de todos los registros de la tabla.

    Para verificar el resultado de la operación, se utiliza el método rowCount(), aunque su interpretación en un UPDATE es más sutil que en un INSERT. Este método no devuelve si la consulta se ejecutó, sino el número de filas que fueron efectivamente alteradas. Si se intenta actualizar un registro con valores que ya posee, la consulta se ejecutará con éxito, pero rowCount() devolverá 0 porque no se produjo ningún cambio real en los datos. Por lo tanto, un resultado de 0 no necesariamente indica un fallo; puede significar simplemente que no había ninguna modificación que realizar, una distinción clave para manejar correctamente la lógica de la aplicación.

    Eliminar datos

    La operación de borrado, realizada con la sentencia DELETE de SQL, es la más crítica y peligrosa de todas, ya que es irreversible. Una vez que un registro ha sido eliminado, recuperarlo puede ser imposible. Por esta razón, es fundamental manejar esta operación con el máximo cuidado, asegurándose de que la cláusula WHERE especifique de forma inequívoca el registro o registros que se desean eliminar.

    Omitir la cláusula WHERE en una sentencia DELETE es uno de los errores más catastróficos que se pueden cometer, ya que eliminaría todos los registros de la tabla. Al igual que en las operaciones anteriores, el uso de sentencias preparadas es esencial para el WHERE.

    <?php
    // 1. Incluimos el fichero de conexión.
    require_once 'conexion.php';

    // 2. ID del usuario a eliminar (en un caso real, vendría de una petición GET o POST).
    $id_usuario_a_eliminar = 3;

    try {
        // 3. Preparamos la consulta SQL de eliminación.
        // La cláusula WHERE es absolutamente crucial.
        $sql = "DELETE FROM usuarios WHERE id = :id";
        $stmt = $pdo->prepare($sql);

        // 4. Ejecutamos la consulta, pasando el ID del usuario.
        $stmt->execute([':id' => $id_usuario_a_eliminar]);

        // 5. Verificamos cuántas filas fueron eliminadas.
        $filas_afectadas = $stmt->rowCount();

        if ($filas_afectadas > 0) {
            echo "El usuario con ID $id_usuario_a_eliminar ha sido eliminado con éxito.";
        } else {
            echo "No se encontró ningún usuario con el ID $id_usuario_a_eliminar. No se ha borrado nada.";
        }

    } catch (PDOException $e) {
        die("Error al eliminar el registro: " . $e->getMessage());
    }
?>

    La confirmación de una operación de borrado se realiza, al igual que con UPDATE, a través del método rowCount(). Este nos informa del número de filas que fueron eliminadas por la consulta. Un valor de 1 nos asegura que el registro que buscábamos fue encontrado y eliminado con éxito, mientras que un resultado de 0 indica que ningún registro cumplió la condición de la cláusula WHERE, probablemente porque el ID especificado ya no existía en la tabla.

    Dada la naturaleza irreversible y peligrosa de la sentencia DELETE, en la mayoría de las aplicaciones profesionales se evita su uso directo mediante una técnica llamada borrado lógico ("soft delete"). En lugar de eliminar permanentemente un registro de la base de datos, simplemente se le "marca como borrado". Esto se implementa añadiendo una columna a la tabla, como por ejemplo fecha_borrado (que por defecto es NULL). Así, la operación de "borrar" se convierte en un UPDATE que establece la fecha actual en esa columna (UPDATE usuarios SET fecha_borrado = NOW() WHERE id = :id). Para que el resto de la aplicación funcione como si el registro no existiera, todas las consultas de lectura (SELECT) se modifican para que solo recuperen las filas WHERE fecha_borrado IS NULL. Este enfoque es mucho más seguro y robusto, ya que preserva la integridad histórica de los datos y permite recuperar registros "borrados" de forma sencilla.

    Tabla resumen

    Aquí tienes una tabla resumen que compara las operaciones CRUD (Crear, Leer, Actualizar, Borrar) en SQL con PDO:

    Operación Sentencia SQL Métodos PDO Principales Verificación / Resultado Clave
    Crear INSERT INTO ... prepare(), execute() $pdo->lastInsertId()
    Leer SELECT ... FROM ... prepare(), execute(), fetch()/fetchAll() Devuelve el array de resultados
    Actualizar UPDATE ... SET ... prepare(), execute() $stmt->rowCount()
    Borrar DELETE FROM ... prepare(), execute() $stmt->rowCount()

    Conectando a Bases de Datos NoSQL: MongoDB

    Hasta ahora, nos hemos centrado en las bases de datos relacionales (como MySQL), que organizan los datos en tablas con filas y columnas. Sin embargo, existe otra familia de bases de datos muy popular, conocida como NoSQL. Dentro de esta familia, MongoDB es una de las más utilizadas.

    MongoDB es una base de datos orientada a documentos. En lugar de tablas y filas, almacena los datos en colecciones y documentos. Un documento es una estructura de datos similar a un JSON (técnicamente, se guarda en un formato binario llamado BSON), lo que le da una gran flexibilidad y hace que se mapee de forma muy natural con los objetos y arrays de los lenguajes de programación modernos.

    Para interactuar con MongoDB desde PHP, no se utiliza PDO. MongoDB tiene su propio driver oficial. En el desarrollo moderno, este driver se gestiona a través de Composer. Para empezar un proyecto, primero necesitaríamos instalar la librería correspondiente en nuestra terminal: composer require mongodb/mongodb. Una vez instalada, podemos usar el autoloader de Composer para cargar las clases necesarias.

    La conexión a MongoDB se realiza creando una instancia de la clase MongoDB\Client. Esta clase necesita una URI (Uniform Resource Identifier) de conexión que le indique dónde se encuentra el servidor de la base de datos. Una vez conectado al servidor, podemos seleccionar la base de datos y la colección con la que queremos trabajar.

        <?php
    // 1. Incluimos el autoloader de Composer.
    // Esto es esencial para que PHP pueda encontrar la clase MongoDB\Client.
    require_once 'vendor/autoload.php';

    // 2. URI de conexión.
    // Por defecto, MongoDB se ejecuta en el puerto 27017.
    $uri = 'mongodb://localhost:27017';

    try {
        // 3. Crear una nueva instancia del cliente.
        // Esto establece la conexión con el servidor de MongoDB.
        $cliente = new MongoDB\Client($uri);

        // 4. Seleccionar una base de datos y una colección.
        // Si la base de datos o la colección no existen, MongoDB las creará
        // automáticamente en el momento en que se inserte el primer documento.
        $coleccion = $cliente->mi_tienda->usuarios;

        // Si llegamos aquí, la conexión fue exitosa.
        // Para verificar, podemos contar los documentos en la colección.
        $num_documentos = $coleccion->countDocuments();
        echo "Conexión a MongoDB exitosa. La colección 'usuarios' tiene " . $num_documentos . " documentos.";

    } catch (Exception $e) {
        // Manejo de errores de conexión.
        die("Error al conectar con MongoDB: " . $e->getMessage());
    }

?>

    El proceso de conexión a MongoDB se apoya en varias prácticas del desarrollo moderno en PHP. La primera es el uso del autoloader de Composer. La línea require_once 'vendor/autoload.php'; es un paso crucial que delega a Composer la responsabilidad de la carga de clases. En lugar de tener que escribir manualmente sentencias include o require para cada clase que necesitemos, el autoloader localiza y carga automáticamente las clases (como MongoDB\Client) en el momento exacto en que son utilizadas por primera vez, simplificando enormemente la gestión de dependencias.

    El modelo de conexión presenta una selección diferida, a diferencia del enfoque más directo de PDO. Con MongoDB, el proceso se divide en dos etapas claras: primero, se establece una conexión general con el servidor de bases de datos al crear el objeto new MongoDB\Client, y solo después se selecciona la base de datos y la colección específicas con las que se va a trabajar, utilizando una sintaxis de objeto como $cliente->mi_tienda->usuarios.

    Finalmente, este proceso se beneficia de la naturaleza flexible y sin esquema (schemaless) de MongoDB. No es necesario definir una estructura de tablas o una base de datos de antemano. Si al seleccionar la base de datos mi_tienda o la colección usuarios estas no existen, MongoDB no genera un error. En su lugar, las creará implícitamente en el momento en que se realice la primera operación de escritura, ofreciendo un flujo de desarrollo más ágil y adaptable.

    Consultando Datos en MongoDB

    La consulta de datos en MongoDB difiere fundamentalmente del modelo SQL. En lugar de escribir una cadena de texto con una consulta SELECT, en MongoDB se consultan los datos construyendo un documento de filtro en formato de array asociativo de PHP. Este filtro especifica las condiciones que deben cumplir los documentos para ser seleccionados.

    Las dos operaciones principales para leer datos son findOne(), para obtener un único documento, y find(), para obtener múltiples documentos.

    El método findOne() es ideal cuando buscas un documento específico y sabes que solo habrá un resultado (o solo te interesa el primero), como al buscar un usuario por su email. Devuelve un único documento (como un array asociativo) o null si no encuentra ninguna coincidencia.

    <?php
    require_once 'vendor/autoload.php';

    try {
        $cliente = new MongoDB\Client('mongodb://localhost:27017');
        $coleccion = $cliente->mi_tienda->usuarios;

        // 1. Definimos el filtro de búsqueda.
        // Buscamos un documento cuya clave 'email' sea igual a 'luis.soler@email.com'.
        $filtro = ['email' => 'luis.soler@email.com'];

        // 2. Ejecutamos la consulta.
        $usuario = $coleccion->findOne($filtro);

        // 3. Mostramos el resultado.
        if ($usuario) {
            echo "<h1>Usuario Encontrado</h1>";
            echo "Nombre: " . $usuario['nombre'] . "<br>";
            echo "Email: " . $usuario['email'] . "<br>";
            // El _id es un objeto especial, para verlo como string usamos __toString()
            echo "ID: " . $usuario['_id']->__toString() . "<br>";
        } else {
            echo "No se ha encontrado ningún usuario con ese email.";
        }

    } catch (Exception $e) {
        die("Error al consultar los datos: " . $e->getMessage());
    }
?>

    Por su parte, el método principal para realizar consultas es find(). A diferencia de findOne(), find() no devuelve los datos directamente, sino un objeto especial llamado cursor. Un cursor es un puntero eficiente al conjunto de resultados en el servidor de la base de datos. Para obtener los documentos, simplemente tenemos que iterar sobre este cursor con un bucle foreach.

    El método find() acepta un segundo argumento opcional, un array de opciones, que nos permite ordenar los resultados (sort), limitar el número de documentos devueltos (limit), o seleccionar solo ciertos campos (projection).

    <?php
    require_once 'vendor/autoload.php';

    try {
        $cliente = new MongoDB\Client('mongodb://localhost:27017');
        $coleccion = $cliente->mi_tienda->usuarios;

        // 1. Definimos el filtro: queremos todos los usuarios que estén activos.
        $filtro = ['activo' => true];

        // 2. Definimos las opciones: ordenar por nombre de forma ascendente (1) y limitar a 5 resultados.
        $opciones = [
            'sort' => ['nombre' => 1],
            'limit' => 5
        ];

        // 3. Ejecutamos la consulta find(), que nos devuelve un cursor.
        $cursor = $coleccion->find($filtro, $opciones);

        // 4. Iteramos sobre el cursor para obtener cada documento.
        echo "<h1>Usuarios Activos (limitado a 5)</h1>";
        echo "<ul>";
        foreach ($cursor as $usuario) {
            echo "<li>" . $usuario['nombre'] . " (" . $usuario['email'] . ")</li>";
        }
        echo "</ul>";

    } catch (Exception $e) {
        die("Error al consultar los datos: " . $e->getMessage());
    }
?>

    Nota

    El campo _id de MongoDB no es un simple string o número, sino un tipo de dato especial BSON llamado ObjectId. Si quieres buscar un documento por su _id, debes convertir el string del ID a un objeto ObjectId primero.

    <?php
    // ¡Incorrecto! Esto no encontrará nada.
    // $usuario = $coleccion->findOne(['_id' => '63c8a0b5f1a1b2c3d4e5f6g7']);

    // ¡Correcto! Usamos la clase ObjectId del driver.
    use MongoDB\BSON\ObjectId;
    $id_string = '5f8d6b9f3c7b2a1b3c4d5e6f'; // Un ID de ejemplo
    $usuario = $coleccion->findOne(['_id' => new ObjectId($id_string)]);
?>

    La Inserción de Documentos

    La inserción de datos en MongoDB es un proceso muy directo que refleja la naturaleza del formato de documentos. En lugar de construir una sentencia INSERT de SQL, se construye un documento (un array asociativo en PHP) y se le pasa a un método de inserción. Si la colección en la que intentamos insertar no existe, MongoDB la creará automáticamente.

    Para insertar un único documento utilizamos el método insertOne. Una vez insertado un nuevo documento, devuelve un objeto con información sobre la operación, incluyendo el _id único que MongoDB ha asignado automáticamente al nuevo documento.

    <?php
    require_once 'vendor/autoload.php';

    try {
        $cliente = new MongoDB\Client('mongodb://localhost:27017');
        $coleccion = $cliente->mi_tienda->usuarios;

        // 1. Creamos el documento como un array asociativo en PHP.
        $nuevo_usuario = [
            'nombre' => 'Elena Pascual',
            'email' => 'elena.pascual@email.com',
            'activo' => false,
            'fecha_registro' => new MongoDB\BSON\UTCDateTime()
        ];

        // 2. Ejecutamos la inserción.
        $resultado = $coleccion->insertOne($nuevo_usuario);

        // 3. Obtenemos el ID del documento recién insertado.
        $id_insertado = $resultado->getInsertedId();

        echo "Usuario insertado con éxito.<br>";
        echo "El ID del nuevo usuario es: " . $id_insertado;

    } catch (Exception $e) {
        die("Error al insertar el documento: " . $e->getMessage());
    }
?>

    Por otro lado, si necesitas insertar múltiples documentos a la vez, el método insertMany() es mucho más eficiente que llamar a insertOne() en un bucle, ya que reduce el número de viajes de ida y vuelta a la base de datos. Este método acepta un array de documentos.

    <?php
    require_once 'vendor/autoload.php';

    try {
        $cliente = new MongoDB\Client('mongodb://localhost:27017');
        $coleccion = $cliente->mi_tienda->usuarios;

        // 1. Creamos un array que contiene los documentos a insertar.
        $nuevos_usuarios = [
            [
                'nombre' => 'Pedro Jimenez',
                'email' => 'pedro.j@email.com',
                'activo' => true,
                'fecha_registro' => new MongoDB\BSON\UTCDateTime()
            ],
            [
                'nombre' => 'Sofia Lopez',
                'email' => 'sofia.l@email.com',
                'activo' => true,
                'fecha_registro' => new MongoDB\BSON\UTCDateTime()
            ]
        ];

        // 2. Ejecutamos la inserción múltiple.
        $resultado = $coleccion->insertMany($nuevos_usuarios);

        // 3. Obtenemos el número de documentos insertados y sus IDs.
        $documentos_insertados = $resultado->getInsertedCount();
        $ids_insertados = $resultado->getInsertedIds();

        echo $documentos_insertados . " usuarios han sido insertados con éxito.<br>";
        echo "Los nuevos IDs son:<br>";

        foreach ($ids_insertados as $id) {
            echo "- " . $id . "<br>";
        }

    } catch (Exception $e) {
        die("Error al insertar los documentos: " . $e->getMessage());
    }
?>

    La Actualización de Documentos

    La actualización de datos en MongoDB es una operación muy potente. A diferencia de SQL, donde se construye una sentencia UPDATE, en MongoDB se utilizan dos arrays asociativos: un filtro para especificar qué documentos se van a modificar, y un documento de actualización para especificar cómo se van a modificar.

    La clave del documento de actualización son los operadores de actualización. El más común es $set, que se utiliza para modificar el valor de campos específicos sin tener que reemplazar el documento entero.

    El método updateOne busca el primer documento que coincida con el filtro y le aplica la actualización. Es ideal para modificar un registro específico, por ejemplo, un usuario identificado por su _id.

    <?php
    require_once 'vendor/autoload.php';
    use MongoDB\BSON\ObjectId;

    try {
        $cliente = new MongoDB\Client('mongodb://localhost:27017');
        $coleccion = $cliente->mi_tienda->usuarios;

        // 1. Filtro: Seleccionamos al usuario por su ID.
        $filtro = ['_id' => new ObjectId('ID_DEL_USUARIO_A_CAMBIAR')];

        // 2. Documento de Actualización: Usamos $set para cambiar el email y el estado.
        $actualizacion = [
            '$set' => [
                'email' => 'nuevo.email.elena@email.com',
                'activo' => true
            ]
        ];

        // 3. Ejecutamos la actualización.
        $resultado = $coleccion->updateOne($filtro, $actualizacion);

        // 4. Verificamos el resultado.
        $documentos_modificados = $resultado->getModifiedCount();

        if ($documentos_modificados > 0) {
            echo "El usuario ha sido actualizado con éxito.";
        } else {
            echo "No se encontró el usuario o los datos ya eran los mismos.";
        }

    } catch (Exception $e) {
        die("Error al actualizar el documento: " . $e->getMessage());
    }
?>

    Por su parte, el método updateMany() aplica la actualización a todos los documentos que coincidan con el criterio del filtro. Es muy potente para realizar cambios en lote.

    <?php
    require_once 'vendor/autoload.php';
    use MongoDB\BSON\UTCDateTime;

    try {
        $cliente = new MongoDB\Client('mongodb://localhost:27017');
        $coleccion = $cliente->mi_tienda->usuarios;

        // 1. Filtro: Seleccionamos a todos los usuarios que estén inactivos.
        $filtro = ['activo' => false];

        // 2. Actualización: Los activamos y añadimos un campo con la fecha de modificación.
        $actualizacion = [
            '$set' => [
                'activo' => true,
                'ultima_modificacion' => new UTCDateTime()
            ]
        ];

        // 3. Ejecutamos la actualización múltiple.
        $resultado = $coleccion->updateMany($filtro, $actualizacion);

        // 4. Verificamos cuántos documentos se modificaron.
        $documentos_modificados = $resultado->getModifiedCount();

        echo $documentos_modificados . " usuarios han sido activados.";

    } catch (Exception $e) {
        die("Error al actualizar los documentos: " . $e->getMessage());
    }
?>

    La pieza central de una operación de actualización en MongoDB es el operador $set. Esta es la forma más común y eficiente de modificar un documento, ya que realiza un cambio a nivel de campo. Esto significa que solo altera los campos especificados en el documento de actualización, dejando el resto de la estructura y los datos del documento intactos. MongoDB ofrece un rico lenguaje de actualización con muchos otros operadores atómicos, como $inc para incrementar valores numéricos o $push para añadir elementos a un array, lo que permite realizar modificaciones de datos muy potentes y específicas.

    Para verificar el resultado de la operación, el objeto devuelto por los métodos updateOne o updateMany nos ofrece el método getModifiedCount(). Es importante entender que este método informa de cuántos documentos fueron efectivamente cambiados. Si un documento coincide con el filtro de búsqueda pero ya contiene los valores que se intentan establecer, la operación tendrá éxito, pero getModifiedCount() devolverá 0, proporcionando una retroalimentación precisa sobre si la operación resultó en un cambio real en los datos.

    Finalmente, es importante conocer una alternativa a la actualización por campos: el método replaceOne(). A diferencia de updateOne, que modifica partes de un documento, replaceOne() reemplaza por completo el primer documento que coincide con el filtro por un nuevo documento que le proporcionamos, conservando únicamente el _id original. Aunque puede ser útil en ciertos casos, generalmente es menos eficiente que usar updateOne con el operador $set si el objetivo es solo cambiar algunos campos, ya que implica reescribir el documento entero.

    La Eliminación de Documentos

    La eliminación de datos es la operación final del ciclo CRUD (Crear, Leer, Actualizar, Borrar). En MongoDB, al igual que en las operaciones de lectura y actualización, se utiliza un documento de filtro para especificar qué documentos deben ser eliminados. Es una operación permanente e irreversible, por lo que debe ser manejada con extremo cuidado.

    Al igual que ocurre con las anteriores operaciones del CRUD, existe el método deleteOne que busca el primer documento que coincida con el filtro y lo elimina de la colección. Es la operación segura para borrar un registro específico.

    <?php
    require_once 'vendor/autoload.php';
    use MongoDB\BSON\ObjectId;

    try {
        $cliente = new MongoDB\Client('mongodb://localhost:27017');
        $coleccion = $cliente->mi_tienda->usuarios;

        // 1. Filtro: Seleccionamos al usuario que queremos eliminar por su ID.
        $filtro = ['_id' => new ObjectId('ID_DEL_USUARIO_A_ELIMINAR')];

        // 2. Ejecutamos la eliminación.
        $resultado = $coleccion->deleteOne($filtro);

        // 3. Verificamos el resultado.
        $documentos_eliminados = $resultado->getDeletedCount();

        if ($documentos_eliminados > 0) {
            echo "El usuario ha sido eliminado con éxito.";
        } else {
            echo "No se encontró ningún usuario con ese ID.";
        }

    } catch (Exception $e) {
        die("Error al eliminar el documento: " . $e->getMessage());
    }
?>

    También está el método deleteMany que elimina todos los documentos que coincidan con el criterio del filtro. Es una operación muy potente y potencialmente peligrosa si el filtro no es lo suficientemente específico.

    <?php
    require_once 'vendor/autoload.php';

    try {
        $cliente = new MongoDB\Client('mongodb://localhost:27017');
        $coleccion = $cliente->mi_tienda->usuarios;

        // 1. Filtro: Seleccionamos a todos los usuarios que estén marcados como inactivos.
        $filtro = ['activo' => false];

        // 2. Ejecutamos la eliminación múltiple.
        $resultado = $coleccion->deleteMany($filtro);

        // 3. Verificamos cuántos documentos se eliminaron.
        $documentos_eliminados = $resultado->getDeletedCount();

        echo $documentos_eliminados . " usuarios inactivos han sido eliminados.";

    } catch (Exception $e) {
        die("Error al eliminar los documentos: " . $e->getMessage());
    }
?>

    Advertencia

    Ejecutar $coleccion->deleteMany([]); (con un filtro vacío) eliminará TODOS los documentos de la colección. Es una operación extremadamente destructiva que debe ser utilizada con la máxima precaución..

    Al igual que con las bases de datos SQL, la práctica profesional recomendada es a menudo evitar el borrado físico. La técnica del borrado lógico es perfectamente aplicable a MongoDB. En lugar de ejecutar un deleteOne o deleteMany, se realizaría una operación updateOne o updateMany para añadir un campo que marque el documento como borrado, por ejemplo:

    ['$set' => ['fecha_borrado' => new MongoDB\BSON\UTCDateTime()]]

    Posteriormente, todas las consultas de la aplicación (find, findOne, etc.) deberían incluir un filtro para excluir estos documentos, como ['fecha_borrado' => ['$exists' => false]]. Esto preserva los datos y hace la aplicación mucho más robusta y segura.
