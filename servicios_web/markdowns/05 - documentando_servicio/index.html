    Documentación de un Servicio Web

    Una API es una interfaz de comunicación; por lo tanto, es inútil si los desarrolladores que la van a consumir no disponen de un manual de instrucciones claro y preciso. La documentación de una API es una parte tan crucial como el propio código, ya que explica qué endpoints están disponibles, qué operaciones se pueden realizar, qué parámetros se esperan y qué estructura tienen los datos que devuelve.

    Aunque en el pasado la documentación se creaba manualmente en ficheros de texto o wikis, este enfoque era frágil y propenso a quedar desactualizado. La solución moderna es describir la API utilizando un estándar formal y legible por máquinas. Aquí es donde entran en juego Swagger y la OpenAPI Specification (OAS).

    La OpenAPI Specification es un estándar (escrito en formato JSON o YAML) que permite crear un "contrato" o "plano" de tu API. Swagger es el conjunto de herramientas más popular que utiliza esta especificación para, entre otras cosas, generar automáticamente una documentación interactiva. Esto permite a los consumidores de tu API no solo leer qué hace cada endpoint, sino también probarlos directamente desde el navegador, haciendo que el proceso de integración sea mucho más rápido y sencillo.

    Integrando Swagger en Laravel con l5-swagger

    Integrar Swagger en Laravel se realiza a través de paquetes de la comunidad que leen tu código y generan la documentación automáticamente. El paquete más popular y robusto para esta tarea es darkaonline/l5-swagger. Este se encarga de generar la especificación OpenAPI a partir de anotaciones en tu código PHP y de mostrarla a través de una interfaz de Swagger UI.

    El primer paso es añadir el paquete a tu proyecto utilizando Composer. Abre tu terminal en la raíz del proyecto y ejecuta:

    composer require darkaonline/l5-swagger

    A continuación, necesitas publicar los ficheros de configuración y las vistas del paquete en tu propia aplicación para poder personalizarlos. Ejecuta el siguiente comando de Artisan:

    php artisan vendor:publish --provider "L5Swagger\L5SwaggerServiceProvider"

    Este comando creará principalmente el fichero config/l5-swagger.php.

    Documentar controladores

    El paquete l5-swagger utiliza otra librería muy potente por debajo, llamada swagger-php, para leer y procesar los comentarios de tu código. La idea es que la documentación no viva en un fichero separado que pueda quedar desactualizado, sino que resida junto al código que describe.

    Esto se logra a través de anotaciones, que son comentarios especiales que siguen la sintaxis del estándar OpenAPI. Estos comentarios empiezan con /** y utilizan etiquetas que comienzan con @OA\ (de OpenAPI) para definir cada parte de la API.

    El primer paso es definir la información global de tu API, como su título y descripción. Esto actúa como la portada de tu documentación. La mejor práctica es colocar este bloque en un lugar central de tu aplicación, como el controlador base en app/Http/Controllers/Controller.php, ya que es un fichero que siempre está presente.

    <?php 
  namespace App\Http\Controllers;

  use Illuminate\Foundation\Auth\Access\AuthorizesRequests;
  use Illuminate\Foundation\Validation\ValidatesRequests;
  use Illuminate\Routing\Controller as BaseController;

  /**
   * @OA\Info(
   * version="1.0.0",
   * title="Mi API de Libros",
   * description="Descripción detallada de la API para gestionar el catálogo de libros.",
   * @OA\Contact(
   * email="api-support@ejemplo.com"
   * ),
   * @OA\License(
   * name="Apache 2.0",
   * url="http://www.apache.org/licenses/LICENSE-2.0.html"
   * )
   * )
   */
  class Controller extends BaseController
  {
      use AuthorizesRequests, ValidatesRequests;
  }
?>

    Documentar un Endpoint

    Ahora, vamos a documentar una ruta específica. Cada método de tu controlador que responda a una ruta de la API debería tener un bloque de anotaciones justo encima que lo describa. Analicemos un ejemplo completo para el método show de nuestro Api/BookController.

    <?php 
  // app/Http/Controllers/Api/BookController.php

  class BookController extends Controller
  {
      /**
       * @OA\Get(
       * path="/api/books/{id}",
       * operationId="getBookById",
       * tags={"Libros"},
       * summary="Obtener información de un libro",
       * description="Devuelve los datos de un único libro especificado por su ID.",
       * @OA\Parameter(
       * name="id",
       * description="ID del libro",
       * required=true,
       * in="path",
       * @OA\Schema(
       * type="integer"
       * )
       * ),
       * @OA\Response(
       * response=200,
       * description="Operación exitosa",
       * @OA\JsonContent(ref="#/components/schemas/BookResource")
       * ),
       * @OA\Response(
       * response=404,
       * description="Libro no encontrado"
       * )
       * )
       */
      public function show(Book $book)
      {
          return new BookResource($book);
      }
  }
?>

    Anotaciones de Swagger

    Aquí tienes una tabla resumen con las principales anotaciones de OpenAPI (Swagger) que se utilizan para documentar una API en Laravel con el paquete l5-swagger.

    Anotación Propósito Atributos y Uso Clave
    Información General
    @OA\Info Define la información principal de la API. title, version, description, @OA\Contact
    Definición de Endpoints
    @OA\Get, Post, Put, Delete Describe una operación para un endpoint específico. path, summary, description, tags
    @OA\Parameter Define un parámetro que acepta la operación. name, in ('path', 'query'), required, description, @OA\Schema
    @OA\RequestBody Describe el cuerpo de una petición (POST, PUT, etc.). description, required, @OA\JsonContent
    @OA\Response Describe una posible respuesta de la operación. response (código HTTP, ej: 200, 404), description, @OA\JsonContent
    Descripción de Datos
    @OA\Schema Define una estructura de datos reutilizable (un "objeto"). schema (nombre), type, required, @OA\Property
    @OA\Property Define una propiedad dentro de un @OA\Schema. property (nombre), type, description, example
    @OA\JsonContent Especifica que el contenido es JSON y define su estructura. ref (para referenciar un @OA\Schema), type, properties

    Generar la Documentación

    Una vez que has añadido las anotaciones, ejecuta el siguiente comando de Artisan para que l5-swagger las lea y genere el fichero de documentación final (openapi.json):

    php artisan l5-swagger:generate
    ¡Listo! Ahora, con tu servidor en marcha (php artisan serve), visita la URL que el paquete ha creado para la documentación en tu navegador:

    http://localhost:8000/api/documentation

    Verás una interfaz de Swagger UI completamente funcional, interactiva y generada a partir de tu propio código.
