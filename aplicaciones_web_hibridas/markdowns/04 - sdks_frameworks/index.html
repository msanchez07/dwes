    Utilización de Librerías de Código y Frameworks

    Aunque es posible consumir APIs utilizando herramientas de bajo nivel como cURL, en aplicaciones profesionales es mucho más común y recomendable utilizar librerías de cliente HTTP y, cuando estén disponibles, los SDKs (Software Development Kits) oficiales. Estas herramientas nos abstraen de los detalles de la comunicación y nos proporcionan una interfaz más cómoda y robusta.

    Una de las librerías de cliente HTTP más populares para PHP es Guzzle. Su principal ventaja sobre cURL es que ofrece una interfaz orientada a objetos limpia y moderna. Su característica más potente es la gestión de errores basada en excepciones: Guzzle lanzará automáticamente una excepción para los errores HTTP, permitiéndonos capturarlos de forma controlada en un bloque try...catch, lo que hace el código inmensamente más fiable.

    La forma estándar de instalar Guzzle es a través de Composer:

    composer require guzzlehttp/guzzle

    Laravel incluye su propio cliente HTTP nativo basado en Guzzle, accesible a través de la fachada Http::. Este cliente nos proporciona una sintaxis fluida y coherente con el resto del framework, con manejo automático de errores, timeouts configurables y respuestas JSON decodificadas automáticamente.

    Ejemplo con Laravel (Cliente HTTP nativo)

    El cliente HTTP de Laravel nos permite consumir APIs de forma simple y elegante. Veamos cómo reescribiríamos nuestro cliente de TMDb:

    app/Services/TmdbClient.php
    <?php

namespace App\Services;

use Illuminate\Support\Facades\Http;
use Illuminate\Http\Client\ConnectionException;

class TmdbClient {
    public function getPeliculasPopulares(): array {
        try {
            $response = Http::timeout(10)
                ->withHeaders([
                    'Authorization' => 'Bearer ' . config('services.tmdb.api_key'),
                    'Accept' => 'application/json'
                ])
                ->get('https://api.themoviedb.org/3/movie/popular', [
                    'language' => 'es-ES',
                    'page' => 1
                ]);

            // Lanzará excepción automáticamente si hay error HTTP
            $response->throwIf();

            return $response->json('results') ?? [];

        } catch (ConnectionException $e) {
            // Error de conexión (servidor no disponible)
            report($e);
            return [];

        } catch (\Illuminate\Http\Client\RequestException $e) {
            // Error en la respuesta HTTP (404, 500, etc.)
            report($e);
            return [];
        }
    }
}

    Las ventajas de este enfoque son claras: el método throwIf() lanza una excepción automáticamente si la respuesta HTTP indica error (códigos 4xx o 5xx), podemos encadenar métodos para configurar timeouts, y json() decodifica la respuesta automáticamente.

    Cuando usar Guzzle directamente

    Aunque Laravel incluye su propio cliente, hay situaciones donde Guzzle directo puede ser necesario o preferible:

    • Necesitamos control más fino sobre las opciones de configuración
    • Requerimos middleware personalizado para las peticiones
    • La API necesita funcionalidades específicas de Guzzle no abstraídas por Laravel
    Uso de Guzzle directo con Laravel
    <?php

use GuzzleHttp\Client;
use GuzzleHttp\Exception\RequestException;

function getPeliculasPopularesConGuzzle() {
    $client = new Client([
        'base_uri' => 'https://api.themoviedb.org/3/',
    ]);

    try {
        $response = $client->request('GET', 'movie/popular', [
            'query' => [
                'language' => 'es-ES',
                'page' => 1
            ],
            'headers' => [
                'Authorization' => 'Bearer ' . config('services.tmdb.api_key'),
                'Accept' => 'application/json',
            ]
        ]);

        $datos = json_decode($response->getBody(), true);
        return $datos['results'] ?? null;

    } catch (RequestException $e) {
        report($e);
        return null;
    }
}

    SDKs: El Nivel Más Alto de Abstracción

    Si una librería como Guzzle es una navaja suiza para cualquier tipo de petición HTTP, un SDK (Software Development Kit) es una herramienta de precisión diseñada para una API concreta, como la de Stripe para pagos. Al utilizar un SDK, dejamos de pensar en términos de peticiones HTTP para interactuar directamente con objetos que representan los conceptos de negocio del servicio. El SDK se encarga por debajo de toda la comunicación, autenticación y gestión de errores.

    Veamos como utilizar el SDK de Stripe con Laravel. Primero, instalaríamos el SDK oficial vía Composer:

    composer require stripe/stripe-php

    Configuraríamos la clave de API en el archivo .env:

    .env
    STRIPE_SECRET_KEY=sk_test_tu_clave_secreta
STRIPE_PUBLIC_KEY=pk_test_tu_clave_publica

    Y en config/services.php:

    config/services.php
    return [
    // ...
    'stripe' => [
        'secret_key' => env('STRIPE_SECRET_KEY'),
        'public_key' => env('STRIPE_PUBLIC_KEY'),
    ],
];

    El código para realizar una operación es mucho más declarativo. No construimos URLs ni cabeceras, simplemente trabajamos con los objetos que el SDK nos proporcionan:

    app/Http/Controllers/Api/PagoController.php
    <?php

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use Illuminate\Http\Request;
use Stripe\Stripe;
use Stripe\Exception\ApiErrorException;

class PagoController extends Controller {
    public function crearIntencionPago(Request $request) {
        // Configurar la clave de API
        Stripe::setApiKey(config('services.stripe.secret_key'));

        try {
            $paymentIntent = \Stripe\PaymentIntent::create([
                'amount' => $request->input('cantidad', 1099), // en céntimos
                'currency' => 'eur',
                'automatic_payment_methods' => ['enabled' => true],
            ]);

            return response()->json([
                'client_secret' => $paymentIntent->client_secret
            ]);

        } catch (ApiErrorException $e) {
            return response()->json([
                'error' => $e->getMessage()
            ], 500);
        }
    }
}

    La ventaja de este enfoque con SDK es evidente: el código se lee casi como descripción del proceso de negocio. "Crear una intención de pago" es mucho más claro que construir una petition HTTP con autenticación Bearer, headersAccept, y parsear JSON.

    Otros SDKs comunes

    Servicio Paquete Composer Uso común
    Stripe stripe/stripe-php Pagos online
    AWS aws/aws-sdk-php Servicios cloud de Amazon
    Google Cloud google/cloud-* Servicios cloud de Google
    Twilio twilio/sdk SMS y llamadas telefónicas
    Mailchimp mailchimp/marketing Gestión de listas de email

    Cuando una empresa ofrece un SDK oficial para su API, generalmente będzie la opción recomendada. Abstrae complejidades específicas de la API, maneja errores de forma coherente, y often incluye funcionalidades adicionales como reintentos automáticos o caché.
