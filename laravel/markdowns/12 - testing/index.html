    Pruebas y documentación

    Laravel está diseñado para facilitar un flujo de trabajo de desarrollo basado en pruebas, proporcionando herramientas robustas que simplifican el proceso de escribir, ejecutar y documentar tus tests. En este apartado veremos como definir estas pruebas y como documentar tu código.

    Pruebas

    Las pruebas son una parte fundamental del ciclo de vida del desarrollo de software. En Laravel, el framework está diseñado para hacer que las pruebas sean una experiencia agradable y eficiente, proporcionando un entorno robusto y herramientas poderosas para asegurar la calidad y fiabilidad de tu aplicación.

    ¿Por qué es Crucial Realizar Pruebas?

    Integrar pruebas en tu flujo de trabajo de desarrollo ofrece múltiples beneficios:

    1. Detección Temprana de Errores: Identifica bugs y problemas de lógica en las primeras etapas del desarrollo, donde son más fáciles y económicos de corregir.
    2. Confianza en el Código: Te permite realizar cambios, refactorizaciones o añadir nuevas funcionalidades con la seguridad de que no estás rompiendo el código existente.
    3. Documentación Viva: Las pruebas bien escritas pueden servir como una forma de documentación, mostrando cómo se espera que funcione una parte específica de tu aplicación.
    4. Mejora del Diseño: El proceso de escribir pruebas a menudo te obliga a pensar en el diseño de tu código, promoviendo la modularidad y el bajo acoplamiento (lo que se facilita enormemente con la Inyección de Dependencias).
    5. Facilita la Colaboración: En equipos, las pruebas aseguran que los cambios de un desarrollador no afecten negativamente el trabajo de otro.

    El Entorno de Pruebas de Laravel

    Laravel utiliza PHPUnit como su framework de pruebas por defecto, lo que significa que todas las herramientas necesarias para escribir y ejecutar pruebas unitarias vienen integradas desde el inicio.

    Al instalar un nuevo proyecto de Laravel, PHPUnit se incluye automáticamente como dependencia a través de Composer y se configura con un archivo phpunit.xml en la raíz del proyecto. Este archivo define la configuración básica de las pruebas, como:

    • La carpeta donde se encuentran las pruebas.
    • El entorno de ejecución.
    • Opciones específicas para personalizar el comportamiento de PHPUnit.

    Gracias a esta configuración inicial, puedes comenzar a escribir pruebas inmediatamente, sin necesidad de instalar o configurar nada adicional.

    Configuración del Entorno de Pruebas

    Laravel viene con un archivo .env.testing que se carga automáticamente cuando ejecutas tus pruebas. Esto te permite tener una configuración de entorno específica para pruebas (por ejemplo, una base de datos de prueba separada) sin afectar tu entorno de desarrollo o producción.

    # .env.testing
APP_ENV=testing
DB_CONNECTION=sqlite
DB_DATABASE=:memory: # Usa una base de datos en memoria para pruebas rápidas
CACHE_DRIVER=array
SESSION_DRIVER=array
QUEUE_CONNECTION=sync
MAIL_MAILER=array

    Tipos de Pruebas en Laravel

    El ecosistema de Laravel está diseñado para fomentar una cultura de pruebas robusta, ofreciendo herramientas para verificar distintos niveles de la aplicación. Comprender los diferentes tipos de pruebas es crucial para asegurar la estabilidad, fiabilidad y correcto funcionamiento del código. Principalmente, podemos clasificar las pruebas en tres categorías fundamentales: unitarias, de características y de navegador, cada una con un propósito y ámbito de aplicación específicos.

    Pruebas Unitarias (Unit Tests)

    Las pruebas unitarias se centran en verificar la funcionalidad de la unidad de código más pequeña y aislada posible. Esto suele significar probar un método o una clase de manera individual, asegurándose de que su lógica interna sea impecable.

    La característica clave de este tipo de pruebas es que se ejecutan sin depender de elementos externos, como una base de datos, llamadas a API o el sistema de archivos. Para lograr este aislamiento, se utilizan comúnmente simulacros (mocks) de las dependencias, lo que permite testear una única pieza de código en un entorno completamente controlado.

    Este tipo de prueba es ideal para verificar la lógica de negocio de tus clases de servicio, la manipulación de datos en tus modelos (sin interacción con la DB), o el correcto funcionamiento de tus funciones auxiliares (helpers).

    Los archivos de pruebas unitarias se organizan en el directorio tests/Unit para mantener la estructura clara.

    <?php

    // tests/Unit/UserServiceTest.php

    namespace Tests\Unit;

    use PHPUnit\Framework\TestCase;
    use App\Services\UserService; // Suponiendo que tienes un UserService

    class UserServiceTest extends TestCase
    {
        /** @test */
        public function it_can_calculate_user_age()
        {
            $userService = new UserService();
            $birthDate = '1990-05-15';
            $age = $userService->calculateAge($birthDate); // Suponiendo este método

            $this->assertIsInt($age);
            $this->assertGreaterThanOrEqual(30, $age); // Ejemplo de aserción
        }
    }
?>

    Pruebas de Características (Feature Tests)

    Las pruebas de características tienen como objetivo probar la integración de múltiples componentes de la aplicación. Su propósito es asegurar que una "característica" completa, como el registro de un usuario, el envío de un formulario o el flujo de una compra, funcione como se espera.

    A diferencia de las pruebas unitarias, estas pruebas sí interactúan con la base de datos y otros servicios del framework, simulando solicitudes HTTP reales a la aplicación. Son el tipo de prueba más común en Laravel, ya que te permiten verificar de manera integral si las diferentes partes de tu código (controladores, modelos, servicios, etc.) se comunican correctamente entre sí para lograr un resultado final.

    Los archivos de estas pruebas se guardan en el directorio tests/Feature.

    <?php

    // tests/Feature/UserRegistrationTest.php

    namespace Tests\Feature;

    use Illuminate\Foundation\Testing\RefreshDatabase;
    use Tests\TestCase;
    use App\Models\User; // Si vas a interactuar con el modelo User

    class UserRegistrationTest extends TestCase
    {
        use RefreshDatabase; // Reinicia la base de datos para cada prueba

        /** @test */
        public function a_new_user_can_register()
        {
            $response = $this->post('/register', [
                'name' => 'John Doe',
                'email' => 'john@example.com',
                'password' => 'password',
                'password_confirmation' => 'password',
            ]);

            $response->assertRedirect('/home'); // Asume que redirige a /home después del registro
            $this->assertDatabaseHas('users', [
                'email' => 'john@example.com',
            ]);
        }

        /** @test */
        public function registration_requires_a_name()
        {
            $response = $this->post('/register', [
                'email' => 'john@example.com',
                'password' => 'password',
                'password_confirmation' => 'password',
            ]);

            $response->assertSessionHasErrors('name');
        }
    }
?>

    Pruebas de Navegador (Browser Tests)

    Las pruebas de navegador elevan el nivel de integración, ya que van un paso más allá de simular una solicitud HTTP. Utilizando herramientas como Laravel Dusk, estas pruebas simulan la interacción real de un usuario con un navegador web (hacer clic en botones, rellenar formularios, navegar entre páginas, etc.).

    Su propósito es asegurar que la interfaz de usuario (UI) y la experiencia de usuario (UX) se comporten de la manera esperada. Son la forma más efectiva de probar la experiencia completa del usuario, desde el front-end hasta el back-end, y son esenciales para características que dependen en gran medida de JavaScript o de flujos de interacción complejos.

    Los archivos de estas pruebas se encuentran en el directorio tests/Browser.

    Creación y Ejecución de Pruebas

    Laravel simplifica la creación de nuevas clases de prueba a través de su herramienta de línea de comandos, Artisan. Utilizar un comando de Artisan no solo genera el archivo de prueba en el directorio correcto, sino que también incluye la estructura de clase básica necesaria, ahorrando tiempo y asegurando la coherencia en la arquitectura de pruebas.

    # Crear una prueba de característica
php artisan make:test UserRegistrationTest

# Crear una prueba unitaria
php artisan make:test UserTest --unit

# Crear una prueba de navegador (requiere Laravel Dusk)
php artisan make:dusk HomePageTest

    Una vez que has escrito tus clases de prueba, el siguiente paso es ejecutarlas para verificar el comportamiento de tu aplicación. Laravel utiliza PHPUnit como su framework de pruebas, y para ejecutarlo, simplemente debes usar el comando phpunit desde la terminal en la raíz de tu proyecto.

    # Ejecutar todas las pruebas
./vendor/bin/phpunit

# Ejecutar solo las pruebas unitarias
./vendor/bin/phpunit --testsuite Unit

# Ejecutar solo las pruebas de característica
./vendor/bin/phpunit --testsuite Feature

# Ejecutar pruebas de un archivo específico
./vendor/bin/phpunit tests/Feature/UserRegistrationTest.php

# Ejecutar un método de prueba específico
./vendor/bin/phpunit --filter a_new_user_can_register

    Pruebas de Base de Datos

    Laravel facilita enormemente las pruebas que interactúan con la base de datos, proporcionando herramientas que garantizan que el entorno de prueba esté limpio y sea consistente para cada test. Para asegurar que una prueba no afecte a otras y que el estado inicial de la base de datos sea siempre el mismo, Laravel ofrece el trait RefreshDatabase.

    Este "trait" es esencial para las pruebas de característica. Asegura que tu base de datos se migre y se reinicie (o se haga rollback de las transacciones) antes de cada prueba, garantizando un estado limpio y predecible.

    <?php

    namespace Tests\Feature;

    use Illuminate\Foundation\Testing\RefreshDatabase;
    use Tests\TestCase;

    class ProductTest extends TestCase
    {
        use RefreshDatabase; // La base de datos se reiniciará antes de cada método de prueba

        /** @test */
        public function a_product_can_be_created()
        {
            $response = $this->post('/products', [
                'name' => 'Test Product',
                'price' => 19.99,
            ]);

            $response->assertStatus(201); // O el código de estado que esperes
            $this->assertDatabaseHas('products', [
                'name' => 'Test Product',
                'price' => 19.99,
            ]);
        }
    }
?>

    Factories y Seeders

    Para gestionar la creación de datos de prueba de forma programática y eficiente, Laravel proporciona dos herramientas clave que trabajan en conjunto: las Factories y los Seeders. Estas herramientas son esenciales para escribir pruebas que dependen de un estado inicial de la base de datos y para poblar tu entorno de desarrollo.

    Las factories son clases que te permiten definir cómo se generan los datos de tus modelos. En lugar de crear un array de datos manualmente cada vez que necesitas una instancia de un modelo para una prueba, puedes usar una factory para generar datos de forma inteligente. Esto es especialmente útil para campos que necesitan ser únicos (como nombres de usuario o direcciones de correo electrónico) o para datos con formato específico (como fechas o URLs).

    Para generar una factory para un modelo, usa el comando de Artisan make:factory.

    php artisan make:factory PostFactory

    El método definition() de una factory es donde se define el estado por defecto de un modelo. Puedes usar la librería Faker para generar datos falsos de manera conveniente.

    <?php 
    // database/factories/PostFactory.php
    public function definition()
    {
        return [
            'title' => $this->faker->sentence(),
            'body' => $this->faker->paragraph(),
        ];
    }
?>

    Puedes usar las factories directamente en tus pruebas para crear instancias de modelos sin guardarlos en la base de datos (make) o para crearlos y guardarlos (create).

    <?php
    // En una prueba
    use App\Models\Post;

    // Crear un Post en memoria, sin persistirlo
    $post = Post::factory()->make();

    // Crear 5 Posts en la base de datos
    Post::factory()->count(5)->create();
?>

    Por su parte, los seeders son clases utilizadas para poblar la base de datos con datos de prueba. Son especialmente útiles para crear un gran volumen de datos, a menudo utilizando factories, para probar el rendimiento o la paginación de una aplicación. Los seeders se ejecutan manualmente y te dan control sobre el tipo y la cantidad de datos que se crean.

    Usa el comando make:seeder de Artisan para generar una nueva clase de seeder:

    php artisan make:seeder PostSeeder

    Fíjate en el método run() de un seeder, que es donde se contiene la lógica para insertar los datos. Puedes usar una factory aquí para generar los datos de forma masiva.

        // database/seeders/PostSeeder.php
    use Illuminate\Database\Seeder;
    use App\Models\Post;

    class PostSeeder extends Seeder
    {
        public function run()
        {
            // Crea 10 posts usando la factory
            Post::factory()->count(10)->create();
        }
    }
?>

    Por último, para ejecutar el seeder, usa el comando db:seed. Puedes especificar un seeder en particular o ejecutar el DatabaseSeeder, que a su vez puede llamar a otros seeders.

    # Ejecutar un seeder específico
php artisan db:seed --class=PostSeeder

# Ejecutar el DatabaseSeeder (y todos los seeders que llame)
php artisan db:seed

    La combinación de factories y seeders proporciona un sistema potente y flexible para generar datos de prueba, lo que te permite mantener la fiabilidad de tus tests y acelerar el desarrollo de tu aplicación.

    Mocks y Fakes: Simulando Dependencias

    Una de las mayores ventajas de la Inyección de Dependencias (DI) es su impacto directo en la calidad y facilidad de las pruebas unitarias. Al desacoplar una clase de sus dependencias, se obtiene la capacidad de "mockear" o simular esas dependencias durante el proceso de testing.

    Esto significa que, en lugar de interactuar con una base de datos real, un servicio externo o una API, puedes inyectar un objeto simulado (un mock) que imite el comportamiento de la dependencia. Este mock te permite controlar el entorno de la prueba, asegurando que la unidad de código que estás probando se comporte de forma predecible y que los resultados sean fiables, independientemente de factores externos. Al aislar la unidad de código, te aseguras de que cualquier error detectado en la prueba se deba a un fallo en la lógica de la unidad, y no en la de sus colaboradores. Este enfoque no solo simplifica las pruebas, sino que también las hace más rápidas y consistentes.

    Mocks (Mockery)

    Para facilitar el "mockeo" de dependencias en tus pruebas, Laravel integra y configura la librería Mockery de manera nativa. Mockery es un framework de objetos mock muy potente que te permite simular el comportamiento de cualquier clase, lo que es esencial para el desarrollo de pruebas unitarias.

    <?php

    // tests/Feature/OrderProcessingTest.php

    namespace Tests\Feature;

    use App\Services\PaymentGateway; // Suponiendo una interfaz o clase PaymentGateway
    use Illuminate\Foundation\Testing\RefreshDatabase;
    use Mockery\MockInterface;
    use Tests\TestCase;

    class OrderProcessingTest extends TestCase
    {
        use RefreshDatabase;

        /** @test */
        public function an_order_can_be_processed_with_mocked_payment_gateway()
        {
            // Creamos un mock de PaymentGateway y lo registramos en el contenedor
            $this->mock(PaymentGateway::class, function (MockInterface $mock) {
                // Definimos el comportamiento esperado del mock
                $mock->shouldReceive('charge')
                    ->once() // Esperamos que el método 'charge' sea llamado una vez
                    ->with(1000, 'usd') // Con estos argumentos
                    ->andReturn(true); // Y que devuelva true
            });

            // Ahora, cuando el código de la aplicación intente resolver PaymentGateway,
            // recibirá nuestro mock.
            $response = $this->post('/orders', [
                'amount' => 1000,
                'currency' => 'usd',
                // ... otros datos del pedido
            ]);

            $response->assertStatus(200);
            $this->assertDatabaseHas('orders', ['status' => 'completed']);
        }
    }
?>

    Fakes de Laravel

    Laravel proporciona "fakes" para muchos de sus servicios integrados (Mail, Event, Notification, Bus, Http, etc.). Estos fakes te permiten probar la interacción con estos servicios sin que realmente se ejecuten, lo que es ideal para pruebas rápidas y aisladas.

    <?php

    // tests/Feature/UserNotificationsTest.php

    namespace Tests\Feature;

    use App\Notifications\WelcomeNotification;
    use App\Models\User;
    use Illuminate\Foundation\Testing\RefreshDatabase;
    use Illuminate\Support\Facades\Notification; // Importa el Facade de Notification
    use Tests\TestCase;

    class UserNotificationsTest extends TestCase
    {
        use RefreshDatabase;

        /** @test */
        public function a_welcome_notification_is_sent_on_registration()
        {
            Notification::fake(); // Evita que se envíen notificaciones reales

            $user = User::factory()->create([
                'name' => 'Jane Doe',
                'email' => 'jane@example.com',
            ]);

            // Simula el proceso de registro que debería enviar la notificación
            // (esto podría ser una llamada a un controlador, un job, etc.)
            // Por ejemplo, si la notificación se envía en el evento UserRegistered:
            // event(new UserRegistered($user));

            // Para este ejemplo, llamamos directamente al método de notificación
            $user->notify(new WelcomeNotification());

            // Verificamos que la notificación fue enviada al usuario correcto
            Notification::assertSentTo(
                $user,
                WelcomeNotification::class,
                function ($notification, $channels) use ($user) {
                    return $notification->user->id === $user->id;
                }
            );

            // También puedes verificar que no se envió una notificación específica
            // Notification::assertNotSentTo($user, AnotherNotification::class);
        }
    }
?>

    Documentación

    Documentar tus pruebas es una práctica fundamental para que el código sea comprensible para otros desarrolladores y para ti mismo en el futuro. PHPUnit, el framework de pruebas de Laravel, utiliza anotaciones de PHP (comentarios especiales) para enriquecer la información de tus pruebas.

    El bloque de comentarios (DocBlock) sobre una clase o un método de prueba es el lugar ideal para documentar su propósito, comportamiento esperado y cualquier otro detalle relevante. Estos comentarios se escriben utilizando /** ... */.

    <?php
    /**
     * Título de la prueba o clase.
     *
     * Una descripción más detallada de lo que hace esta prueba o clase,
     * qué escenario cubre y por qué es importante.
     *
     * @param  string  $parametro Opcional: describe un parámetro.
     * @return string Opcional: describe el valor de retorno.
     */
?>

    Aquí tienes un resumen de las anotaciones de PHPUnit más comunes, presentadas en una tabla para facilitar su consulta y comprensión.

    Anotación Propósito Ejemplo de Uso
    @test Marca un método como un método de prueba. Es una alternativa explícita a nombrar el método con el prefijo test_. /** @test */
    public function el_usuario_puede_iniciar_sesion() { ... }
    @group Asigna un grupo a una prueba o a toda una clase. Permite ejecutar subconjuntos de pruebas de forma selectiva. /** @group authentication */
    class AuthTest extends TestCase { ... }
    // Terminal: phpunit --group authentication
    @covers Indica qué método o clase está siendo cubierta por la prueba. Útil para la legibilidad y la generación de reportes de cobertura de código. /** @covers \App\Services\Calculator::add */
    public function la_suma_de_dos_numeros_es_correcta() { ... }
    @depends Establece una dependencia entre pruebas. Una prueba no se ejecutará si la prueba de la que depende falla. /** @depends test_a_new_order_can_be_created */
    public function test_an_order_can_be_shipped($orderId) { ... }
    @dataProvider Permite pasar conjuntos de datos a un mismo método de prueba, evitando la repetición de código para probar diferentes escenarios. /** @dataProvider additionProvider */
    public function test_la_suma_funciona($a, $b, $expected) { ... }
