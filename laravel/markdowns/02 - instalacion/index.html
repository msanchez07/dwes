    Instalación y primeros pasos

    Ahora que entendemos qué es un framework y por qué es útil, vamos a dar el primer paso práctico: instalar Laravel y poner en marcha un nuevo proyecto. Afortunadamente, gracias a Composer, este proceso es increíblemente sencillo y estandarizado.

    Prerrequisitos

    Antes de empezar, necesitas tener un entorno de desarrollo local configurado en tu máquina que incluya:

    1. PHP: Laravel 12 (la versión actual a fecha de hoy) requiere PHP 8.2 o superior.
    2. Composer: Como hemos visto, Laravel utiliza Composer para gestionar sus dependencias. Es un requisito indispensable.
    3. Extensiones de PHP: Ciertas extensiones de PHP deben estar habilitadas (como Ctype, JSON, PDO, etc.). Un paquete de desarrollo estándar como XAMPP, MAMP o Laragon generalmente las incluye todas.

    El Proceso de Instalación Vía Composer 🔗

    El método universal y recomendado para crear un nuevo proyecto de Laravel es a través de Composer. Para ello, abriremos nuestra terminal o línea de comandos, navegaremos hasta la carpeta donde guardamos nuestros proyectos (p. ej., htdocs si usas XAMPP) y ejecutaremos el siguiente comando:

    composer global require laravel/installer

    Esta instrucción instalara Laravel en nuestro sistema y lo dejará preparado para poder ejecutar la creación de una nueva aplicación.

    Crear un nuevo proyecto

    Una vez que haya instalado PHP, Composer y el instalador de Laravel, estarás listo para crear una nueva aplicación. El instalador de Laravel solicitará que selecciones su marco de prueba, base de datos y kit de inicio preferidos. Veamos paso a paso este proceso:

    laravel new mi-proyecto

    Al ejecutar el comando sin ningún parámetro, Laravel iniciará el proceso de un proyecto "minimal" al cual deberemos indicarle una serie de parámetros. Los dejaremos tal y como se muestra a continuación:

    Veamos un poco para que sirve cada uno de ellos:

    • app/ → Código principal de tu aplicación (controladores, modelos, proveedores de servicios, jobs…).
    • bootstrap/ → Archivos que inician Laravel y preparan el framework antes de procesar una petición.
    • config/ → Archivos de configuración (base de datos, correo, sesión, etc.).
    • database/ → Migraciones, fábricas y semillas para la base de datos.
    • public/ → Único directorio accesible desde el navegador; contiene index.php y archivos estáticos públicos.
    • resources/ → Archivos sin compilar: vistas Blade, CSS, JS y plantillas de frontend.
    • routes/ → Archivos donde defines las rutas HTTP o de consola.
    • storage/ → Almacenamiento interno: logs, cachés, sesiones y archivos generados por la app.
    • tests/ → Pruebas unitarias y funcionales.
    • vendor/ (no está en git) → Dependencias PHP instaladas con Composer.
    • node_modules/ (no está en git) → Dependencias JavaScript instaladas con npm/pnpm/yarn.

    En cuanto a lso archivos raíz, tenemos los siguientes:

    • artisan → Script CLI para ejecutar comandos de Artisan.
    • composer.json → Lista de dependencias PHP y configuración de autoloading.
    • composer.lock → Versiones exactas de dependencias PHP instaladas.
    • package.json → Lista de dependencias JavaScript y scripts de desarrollo.
    • vite.config.js → Configuración de Vite para compilar y servir assets.
    • .env → Variables de entorno (configuración sensible para la app, no se sube a git).
    • .env.example → Plantilla base del archivo .env.
    • phpunit.xml → Configuración de PHPUnit para ejecutar pruebas.
    • README.md → Información y documentación del proyecto.

    Ejecutando el Entorno de Desarrollo

    El desarrollo moderno en Laravel requiere de dos procesos principales que se ejecutan de forma simultánea, normalmente en dos ventanas de terminal separadas. Uno se encarga del backend (PHP) y el otro del frontend (CSS y JavaScript).

    Laravel incluye su propio servidor de desarrollo gracias a su interfaz de línea de comandos, Artisan. Este servidor es ligero y perfecto para trabajar en local.

    Para iniciarlo, navega hasta la raíz de tu proyecto (mi-proyecto) en una terminal y ejecuta:

    php artisan serve

    La terminal te mostrará un mensaje indicando que el servidor está activo, generalmente en http://127.0.0.1:8000.

    INFO  Server running on [[http://127.0.0.1:8000](http://127.0.0.1:8000)].

Press Ctrl+C to stop the server

    Debes tener en cuenta, que la página de bienvenida que Laravel crea por defecto (resources/views/welcome.blade.php) ya incluye la directiva @vite para cargar sus hojas de estilo y JavaScript. Esto lo veremos más adelante, pero debes tener en cuenta que si solo ejecutas php artisan serve y visitas la página, ocurrirá lo siguiente:

    1. Laravel intentará renderizar la vista welcome.blade.php.
    2. Llegará a la directiva @vite.
    3. La directiva intentará conectar con el servidor de desarrollo de Vite (que no está en marcha).
    4. Al no encontrarlo, buscará los ficheros de producción compilados (en public/build), que tampoco existen en una instalación nueva.
    5. El resultado será un error en la página, normalmente un "Vite manifest not found".

    Para poder trabajar únicamente con php artisan serve y centrarte en el backend por ahora, tienes una opción muy sencilla: compilar los assets una sola vez.

    1. Instala las dependencias de frontend (solo la primera vez): 
      npm install
    2. Compila los assets para producción: 
      npm run build

    Este último comando creará una carpeta public/build con los ficheros CSS y JS ya compilados y optimizados. Ahora, la directiva @vite, al no encontrar el servidor de desarrollo, encontrará estos ficheros y cargará la página sin problemas.

    Configuración 🔗

    La carpeta config en un proyecto de Laravel 12 contiene los ficheros de configuración de la aplicación. Estos ficheros te permiten personalizar aspectos clave como la base de datos, la sesión o el correo. La configuración se lee a través de la función config() y a menudo obtiene sus valores del fichero .env para mantener las credenciales y los datos sensibles fuera del código.

    Al crear un nuevo proyecto, encontrarás solo un puñado de ficheros de configuración esenciales. Estos son los más importantes:

    • app.php: El fichero de configuración principal. Aquí se definen aspectos generales como el nombre de la aplicación, el entorno (APP_ENV), el modo de depuración (APP_DEBUG), la zona horaria, la configuración regional y los proveedores de servicios (providers).

    • auth.php: Define todo lo relacionado con la autenticación. Configura los "guards" (cómo se autentican los usuarios, p. ej., a través de sesiones o tokens) y los "providers" (de dónde se obtienen los usuarios, p. ej., la tabla users de la base de datos).

    • database.php: Aquí se configuran todas las conexiones a las bases de datos. Puedes definir múltiples conexiones (MySQL, PostgreSQL, SQLite, etc.) y especificar cuál usar por defecto.

    • session.php: Gestiona el comportamiento de las sesiones de usuario, incluyendo el "driver" (cómo se guardan las sesiones: fichero, cookie, base de datos, Redis), el tiempo de vida de la sesión y el nombre de la cookie de sesión.

    • hashing.php: Configura el driver para el "hasheo" de contraseñas, que por defecto es Bcrypt.

    Configurando la base de datos

    El fichero config/database.php es el centro de control para todas las interacciones de tu aplicación con las bases de datos. Su función principal es definir las conexiones que tu aplicación puede utilizar. Laravel está diseñado para poder trabajar con múltiples sistemas de bases de datos (MySQL, PostgreSQL, SQLite, etc.) simultáneamente, y es en este fichero donde se especifica cómo conectarse a cada uno de ellos.

    Al abrir el fichero, verás que devuelve un array PHP con una estructura muy clara. Al principio del fichero, encontrarás una clave llamada 'default'. Su valor especifica cuál de las conexiones definidas más abajo se utilizará por defecto en toda la aplicación.

    <?php 
  'default' => env('DB_CONNECTION', 'mysql'),
?>

    Esta línea le dice a Laravel: "Por defecto, usa la conexión que esté definida en la variable DB_CONNECTION del fichero .env. Si esa variable no existe, usa la conexión llamada 'sqlite'".

    Posteriormente tenemos un array asociativo donde cada elemento representa una configuración de conexión completa a una base de datos. Laravel ya viene con ejemplos preconfigurados para los sistemas más comunes: sqlite, mysql, pgsql y sqlsrv.

    Analicemos la configuración típica para una conexión MySQL:

    <?php 
  'mysql' => [
      'driver' => 'mysql',
      'url' => env('DATABASE_URL'),
      'host' => env('DB_HOST', '127.0.0.1'),
      'port' => env('DB_PORT', '3306'),
      'database' => env('DB_DATABASE', 'laravel'),
      'username' => env('DB_USERNAME', 'root'),
      'password' => env('DB_PASSWORD', ''),
      'unix_socket' => env('DB_SOCKET', ''),
      'charset' => 'utf8mb4',
      'collation' => 'utf8mb4_unicode_ci',
      'prefix' => '',
      'strict' => true,
      'engine' => null,
  ],
?>

    • 'driver': Especifica qué tipo de base de datos es. Esto le dice a Laravel qué driver de PDO debe usar.

    • 'host', 'port', 'database', 'username', 'password': Estos son los parámetros de conexión fundamentales. Como puedes ver, cada uno de ellos utiliza la función env() para leer el valor correspondiente del fichero .env. El segundo argumento de la función env() es un valor por defecto que se usará si la variable no está definida en el .env.

    • 'charset' y 'collation': Definen el conjunto de caracteres y la colación para la conexión, siendo utf8mb4 la recomendada para un soporte completo de caracteres Unicode (incluyendo emojis).

    ¿Cómo Modificar la Conexión?

    La forma correcta de modificar la configuración de tu base de datos no es editar directamente el fichero database.php. La idea es mantener este fichero intacto (ya que es parte del código fuente y se versiona en Git) y poner todas tus credenciales y configuraciones específicas del entorno en el fichero .env.

    Esto deberíamos modificar en nuestro fichero .env:

    DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=mi_base_de_datos
DB_USERNAME=mi_usuario
DB_PASSWORD=mi_contraseña_secreta

    El Fichero .env

    Ya hemos visto que los ficheros de la carpeta config utilizan una función env() para obtener sus valores. Ahora vamos a explorar el fichero del que leen esos datos: el fichero .env, uno de los conceptos más importantes para la seguridad y flexibilidad de una aplicación Laravel.

    Una aplicación web nunca se ejecuta en un solo lugar. Como mínimo, existen el entorno de desarrollo local, en el ordenador de cada programador y el entorno de producción, el servidor real donde los usuarios acceden a la aplicación.

    Estos entornos necesitan configuraciones diferentes. La base de datos local no será la misma que la de producción, las claves de APIs pueden ser de prueba o reales, y el modo de depuración debe estar activado en local pero desactivado en producción.

    Si escribiéramos estos valores directamente en los ficheros de config, tendríamos que cambiar el código cada vez que subimos la aplicación al servidor, un proceso manual y muy propenso a errores.

    El fichero .env, que se encuentra en la raíz de tu proyecto Laravel, resuelve este problema. Es un simple fichero de texto plano que define variables de entorno en un formato de CLAVE=VALOR.

    Cuando Laravel se inicia, lee este fichero y carga todas estas variables. Luego, los ficheros de la carpeta config utilizan la función env('NOMBRE_VARIABLE', 'valor_por_defecto') para leer estas variables y configurar la aplicación.

    De esta forma, el código de la aplicación (la carpeta config) es el mismo en todas partes. Lo único que cambia es el contenido del fichero .env en cada máquina.

    Debes tener en cuenta que el fichero .env contiene información altamente sensible (credenciales de bases de datos, claves de APIs, etc.). Por esta razón, nunca debe ser incluido en un sistema de control de versiones como Git. De hecho, si miras el fichero .gitignore de un proyecto Laravel, verás que .env ya está en la lista de ficheros a ignorar.

    Entonces, ¿cómo sabe un nuevo desarrollador qué variables necesita configurar? Para eso existe el fichero .env.example. Este es un fichero de plantilla que sí se incluye en Git. Contiene todas las claves necesarias para que la aplicación funcione, pero con valores de ejemplo o vacíos. El primer paso al clonar un nuevo proyecto de Laravel parte siempre de copiar .env.example y renombrarlo a .env y posteriormente de rellenar el nuevo fichero .env con tus propias credenciales locales.

    Con todo esto ya hemos dado unas primeras pinceladas a la configuración inicial de Laravel. Para más información, siempre debes consultar la documentación oficial. En el siguiente apartado ya nos centramos en la definición de rutas.
